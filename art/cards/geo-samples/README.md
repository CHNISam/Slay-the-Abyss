## 可复现装配

仓库内入口只读取四个显式ID的真实Lua绘图表，不从旧layout回填。使用已有、未修改且固定版本的Image Editor检出（不随仓库复制vendor）：

```sh
python scripts/art/assemble-native-card-samples.py --editor /path/to/Miliastra-image-editor-webui
python -m unittest discover -s tests -p test_native_card_samples.py -v
node --test tests/native-bloodletting-fine-strokes.test.mjs
```

编辑器提交必须为 `103025f9095d8089e3f9bf097f4d0c5fe039d546`，其已有 `backend/app/lua_scene.read_drawing` 为实际解析入口。装配器只在读取后的文本中将CRLF规范化为LF，真实解析入口与 `source.sha256` 都使用该同一文本；这与法律登记和JS检查的既有LF规范化约定一致，LF/CRLF检出生成相同layout，不重写源文件或改变其它字符。脚本运行前拒绝输出与任一Lua、JSON或脚本本身的同路径/符号链接/硬链接别名，以及越出仓库的符号链接，避免覆盖输入。

装配只接受同一144×34硬矩形裁切：拒绝偏移、不等价形状、羽化、反向蒙版、错误父坐标语义和超出窗口的未蒙版图元。浮点容差仍为 **0.0001**，不提高门槛。当前最大边界/中心误差为重剑 `5.4834354e-5`、透支 `5.9982417e-5`、招架还击 `6.6839204e-5`、震慑敌阵 `5.2636719e-5`；这是既有序列化误差范围内的几何裁切证明，**不是数学或像素完全一致声明**。

CI单元测试不需要编辑器检出：Python覆盖几何拒绝、池、文件别名预检以及不依赖编辑器的LF/CRLF CLI一致性；现有锁定 `luaparse` 独立删除编辑器快照后解析四份真实Lua，核对每个槽的字段、源摘要、隐藏尾槽、143控件池和原有两卡不变。生成数据的实际重建需上述固定编辑器。
