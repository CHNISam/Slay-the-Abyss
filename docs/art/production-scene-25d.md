# 岩金封印遗迹：原生图元样板

本样板落实用户已批准的左右同构图：左侧破损石柱、中央战斗留白、右后方遗迹门、冷灰蓝远山与少量琥珀金光。它是供比较路线和审阅画面的一张完整样板，尚未正式装配、导入或通过平台美术验收。

源码基线为 `origin/develop` 的 `518299c`，独立分支 `feat/production-scene-25d`。不修改游戏核心、既有压测场景、任务库或平台正式存档。

## 构图与制作

舞台为 1280×720。几何数据采用左上原点、y 向下；Lua 在创建时转换为平台中心原点、y 向上，并反转二维旋转角。所有图形均为原创组合，没有 PNG 拟合、外部角色图、随机噪声或逐像素描摹。

- 破柱主轴位于 `(123,367)`，有断裂顶面、明暗侧面、嵌槽、裂隙及倾倒柱冠。
- 遗迹门中心约 `(1012,310)`，由门洞、两根墩柱、挑出的柱头、过梁、冠石、台阶组成。细金嵌线和方旋纹强调岩系语言；发光菱形封印悬在门洞中。
- 石台中心 `(639,498)`，外圈约 942×123；上下错开的椭圆表现厚度，24 段透视刻线和少量径向石缝表现封印台。
- 中央 `x=280..870,y=210..415` 保持低细节背景。`y=540..700` 为低对比手牌空间；角色、生命、意图和 HUD 仍由正式界面覆盖，尚未逐屏实机审查。

金色取主题的 `gold #E3B866` 和 `geo #F0B850`。石材和大气使用主题冷灰蓝方向的衍生色，作为此景片的局部美术调色板列在 JSON 中；没有引入按钮、文字或规则语义的新色规范。采用平面色块、有限透明叠色和结构明暗，无法提供位图笔触、柔和渐变、真实投影和复杂体积雾，需与 3D 样板一起人工比较。

## 预算与运行接口

| 视差层 | 图元 | 振幅（设计单位） | 角速度（弧度/秒） |
|---|---:|---:|---:|
| 雾天 | 9 | 0 | 0 |
| 远山 | 19 | 2.2 | 0.13 |
| 门与后方台阶 | 75 | 4 | 0.15 |
| 封印石台与地面 | 51 | 6 | 0.17 |
| 破柱与前景残石 | 53 | 9 | 0.19 |
| 合计 | **207** | | |

合计 **13 个容器**：5 个运动层容器及8个动态子容器。每个子容器最多48张图形，每个运动层最多2个子容器，root 只增加5个直接子容器。没有将207项写成静态UI子树。`show()` 共创建220个动态控件，模板本身的既有节点不计入这个新增数。

```lua
local scene = require('production_25d').new(stage, hostTemplate, imageTemplate)
scene:show()       -- 只构建一次；重复调用不叠加
scene:update(dt)   -- 每帧只移动5个层容器
scene:clear()      -- 运行时切换场景时销毁5个根层及其子树
```

纯2D对照使用 `new(stage, hostTemplate, imageTemplate, {mode='static'})`。它保留完全相同的207图元和13容器，`update()` 不推进时间、不改变任何变换；默认 `parallax` 模式仍更新5个层容器。此对照测的是原生图元绘制的静态背景，不是自定义PNG贴图导入。

离线模式回归：`node node_modules/fengari-node-cli/src/lua-cli.js -e "dofile('art/spikes/art-pressure/verify-production.lua')"`；必须通过 `-e` 执行，让Lua断言失败返回非零退出。覆盖两模式真实模块的207/13计数、静态30帧零移动、默认视差、重复show和clear后重建。它不证明实机显示或手机性能。

模块文件在独立样板目录；打包时可按主控制器约定改模块注册名，不应修改游戏核心。`hostTemplate` 应为无脚本、无额外装饰、无裁剪和无输入阻挡的空容器模板，`imageTemplate` 为无输入阻挡的纯图片模板，二者均仅存为模板。父舞台负责整体缩放：1600×900 对应1.25倍。模块不修改宿主画布尺寸、背景、角色或输入控件。

图形仅使用 `StaticReference 100001/100002/100003`。图片先 `SetImage` 后设置属性；显式激活、显式可见；颜色全部为0–255。首次构建异常会清理已创建的层并抛出诊断，成功打印 `PRODUCTION_25D_READY primitives=207 containers=13 layers=5`。宿主应将异常显示到测试界面。

**平台退出时不要从 `OnDestroy` 调用 `clear()` 或额外 Destroy。** 引擎负责退出销毁；`clear()` 仅用于仍在运行时的主动景片切换。

## 数据与预览维护

- `art/spikes/art-pressure/production-25d.json` 是图形数据源；每项为 `[图形种类, 名称, x, y, 宽, 高, 顺时针角, #RRGGBB, alpha255]`，种类1/2/3对应矩形/椭圆/三角形。
- `production-25d.lua` 的 `LAYERS` 为同一数据的内嵌表，便于平台无需JSON读取器直接运行；其下方生命周期代码独立维护。
- `production-25d.svg` 和 `production-25d.html` 使用同样的207项图形、绘制次序和透明度，没有另加平台无法表达的阴影、滤镜或位图。HTML可暂停视差、显示HUD/主体/手牌避让区；辅助框不属于平台样板。
- 调整 JSON 后，按原行同步 Lua 的 `LAYERS`、SVG节点和 HTML 内嵌数据。更新时保留 Lua 生命周期实现，重新核对图元总数、逐项坐标/颜色、旋转符号、绘制次序。SVG用左上坐标、顺时针角；Lua转换中心坐标和角符号。不得只改预览来掩盖平台差异。
- 石材纹饰集中在门柱、柱头、台阶与封印台；后续追加细节应先在局部完成，一层仍用48项分桶。不要为整屏细节改成数千图元。每次修改后重新统计、导入、读回并截同版本实机证据。
