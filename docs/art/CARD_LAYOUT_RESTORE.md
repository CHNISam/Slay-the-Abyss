# 卡牌布局恢复：30 / 64 与文字兼容分离

复用 TASK-25 / TASK-25.2。修复基准为 `develop@cc091728`，提交 PR 后已同步随后合入的 `develop@fc51f198`，保留其第二幕与节点改动；沿用 `UI_DESIGN.md` 批准的 148×208 卡面，不改规则或卡牌数据。

## 修改范围

- 名称背景恢复 30 高，插图区恢复 144×64。名称和类型的透明原生文字框仍至少 40 高，保持居中；背景条高度不再承担原生短文字兼容职责。
- 战斗、奖励、牌库及商店/节点继续复用 `card-face.mjs`。类型行中心统一，费用、说明与原有点击区域保持原有职责。
- 缺图继续使用明确标记的类型占位，保持 40×40，而不是把方形图标拉伸成横幅。
- `icon.cardPortraits[card_id]` 可为原生图库 ID 条目声明 `size: [源宽, 源高]`。非占位条目按源比例 contain 到 144×64；无尺寸或 placeholder 状态仍按方形占位处理。尺寸必须是两个有限正数，外部图片路径仍不合法。
- 没有新增正式插画绑定。`cleave` 仍是 `placeholder-native-icon`；现有 144×34 离线图元原稿未改、未拉伸、未自动接入。图库 ID 路径不等于复杂图元工厂已经完成。

## 长标题边界

最小字号仍为 14，不截断或改写完整牌名。当前六个原创角色升级名添加全角 `＋` 后会超出标题可读宽度。经 Owner 本轮明确批准，仅在完整名字能放下、升级后缀导致溢出时，将后缀移到现有类型文字中；名称保留绿色升级色。不新增文字控件，短标题和重复升级数字保持原规则表现，复用卡槽会清除旧后缀。

`CardDisplay.title` 的第四个返回值为移出的后缀；三个正式消费者通过统一 `writeTitle` 同时更新名称与类型。只消费前三个返回值的离线调用者不能据此宣称完整升级标记已展示。

## 验证边界

回归覆盖背景和插图区尺寸、透明文字兼容、全标题变体、六个溢出例外、X 费用、重复升级、卡槽复用，以及实际战斗/奖励/牌库/商店对原生图的绑定与等比尺寸。图片尺寸不合法时拒绝更新，不静默拉伸。

前后图来自实际组件和 BattleUI 数据的离线预览。官方图库纹理在离线环境不可用，使用既有共享图形代示；字体为离线近似。透明框矩形有重叠不代表文字字形相互遮挡，但真实字体、换行、图标以及目标设备表现仍须实机确认。

本次没有官方导入、写入游戏存档、启动客户端或手机性能验收。源码/回归通过和 PR/CI 结果分别记录，不宣称视觉验收完成。
