# 卡牌插画：精修重绘质量基线与原创设计流程

2026-10-27 Owner认可10张原作对照实验的**精修版视觉质量**，指定为后续标准。低成本版保留作取舍对照，不作为默认成品。此确认不等于官方导入、游戏字体、XYZ投影、GPU蒙版、十卡同屏或手机性能通过；也不授权把原作插画或描摹当本项目原创资产发布。

复用 TASK-25 / TASK-25.2、现有统一卡面和固定 Image Editor，不另建渲染框架。先做原创代表牌的不同设计，并实际重绘后交审；未经设计认可不恢复75张扩产。不改战斗规则、数值、正式中文名称或既有批准UI。

## 1. 先确定一张图究竟表达什么

每个card_id先从最新`data/cards.json`、默认Run/Combat和`traveler.zh-CN.json`核对名称、真实主效应、对象与代价。设计稿记录：

- 一个主动作；谁作用于谁；单体/多体关系；代价或资源的来源与去向。
- 必须看清的2–3个特征，以及不能为了省图元删掉的接触、连接和遮挡。
- 名称与画面是否相符。例如“星陨剑”应处理陨落/冲击和多个受影响目标，不能只画单剑刺石；不擅自改名迁就画面。
- 次效果、精确数值和选择条件由独立文字承担，不把插画塞成规则流程图。原作没画抽牌或回合数，不意味着本作必须补一堆图标。

首轮代表牌比较两种真正不同的构图，不做同一武器换背景；方向经Owner确认后复用设计约束，不要求所有牌反复生成两版。先遮文字检查主体/动作/对象，再露名称与效果检查是否误导。

## 2. 借鉴原作的方法，不复制原作画面

原作舒服的关键不是重复符号，而是清楚的大轮廓、单一主光、主体与背景明暗分离、明确的运动线/接触点、必要的负空间，以及适量材质层次。背景衬托动作，不和主体争抢。不同技能应有不同场景、视角和动作关系，再通过整体色调与形状语言协调。

不把“原神气质”机械翻译为全金色、每张岩晶、无主剑或盾。旅行者方向保留，但服从技能可读性。复杂手部不作为默认捷径；必要的人物关系用清楚的背影/剪影/局部姿态，不能出现怪异手指或断柄。

原画师访谈提供研究依据：[Anailis Dorta与Bruce Brenneise](https://www.moregamesplease.com/art-in-boardgames/2025/5/27/anailis-dorta-amp-bruce-brenneise-slay-the-spire-art-in-board-games-76)。从卡名/描述发展多个构图，再统一视觉语言；不是从固定物件目录批量套模板。

## 3. 原创源图 → 精修原生 → 完整卡面

1. **源图**：针对当前144×64宽画幅设计；画面不含文字、费用或卡框。AI生成时逐卡/逐变体留提示词、实际输出和SHA，不让模型猜规则。原生直接绘制时如实标明，没有AI位图源就不伪造。旧34高图不能拉伸。
2. **适配**：记录原始尺寸与contain/crop矩形，禁止暗裁掉关键主体。原图适配损失与重绘损失分开比较。
3. **精修**：先主轮廓和关系，再接触/遮挡，再明暗大区，最后有贡献的细节。圆体优先原生ellipse，线/面选择合适图元，不把所有东西拆成昂贵小三角。自动拟合只可作底稿，不冒充精修。
4. **原生图库**：柔光/渐变优先复用已验证索引和现有工具能力，例如当前theme的106056/106057。检查实际Lua的ID、染色、透明度与真实贴图SHA；PNG不能悄悄跳过资源或用假圆替代。不是导入自定义PNG。
5. **装配**：共享cardFace/CardDisplay从真实核心取得名称、费用、说明、升级和动态值。插画与四个文字控件分离。当前148×208卡、30名称背景、144×64画窗、40高透明文字兼容保持；布局以最新运行代码为准。

每个方案交付“原创源图/同窗适配 → 精修原生重绘 → 真实数据完整卡面”，至少含1×和放大检查。只给设计提案或漂亮源图不算这轮完成。

## 4. 双重检查：源意图与输出一致性

- 对照源图逐卡查轮廓、手/武器连接、目标数量、资源方向、前后遮挡。技术重放自身一致不能证明画对。例如本轮Iron Wave曾漏描连续刀面，必须对源修实体，不能叫柔光损失。
- JSON/Lua去可选快照后的真实绘图表、1×/4×重放、完整卡艺术平移、文字生命周期和输入SHA分别验证；修错保留红测，不调阈值刷绿。
- 窄源窗蒙版需核几何；离线8×coverage只是预览近似，不能当官方GPU等价。float32/导出小数导致的像素漂移需定位到图元，修源并记录改变量，不统一粗暴量化。
- 离线字体换行可改善标点与本次常用短语，但不改原生文本/数字/字号/框；单独标注，不能说已修实机字体。

## 5. 成本与放行

单卡图片、蒙版、文字、宿主分别计数；省控件优先删遮挡冗余和1×无贡献细节，保主体关系与层次。少量图库柔光可优于大量硬片。没有统一虚构上限；高成本样张记录风险，不直接扩成十卡同屏。精修基线要求有感染力，不按“控件越少越好”验收。

原创代表稿先由dot自检与独立复核，再请Owner审**设计与实际重绘的对照**。只有Owner满意后扩大对应设计方向。原生导出、写副本、官方导入、真实交互/手机性能继续分层验收，待验不记PASS。
