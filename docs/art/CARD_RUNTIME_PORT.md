## 对照依据与实现

固定参考为[AbstractCard.java](https://github.com/purewhitelove/ButterflyGame/blob/fc379c875c11e008e9c10548ac8e394c301c532f/%E6%9D%80%E6%88%AE%E5%B0%96%E5%A1%94%E5%8E%9F%E7%A0%81/cards/AbstractCard.java)，原字节SHA256为`f11601db66e8df3699481076763b858672ce83d4a6eea6c1abf0715f254b5c5c`，本轮重新取回并与既存参考一致。对照构造时的atlas区域查找、`renderCard`、`renderImage`和`renderPortrait`；反编译文件只留在忽略的研究目录。

| 原版结构 | 本项目迁移 |
|---|---|
| 卡牌身份对应卡图资源，缺资源时有回退 | `abyss_card_display.art()`先查卡牌ID，再使用明确标记的牌型图标占位；不再由各屏分别决定卡图 |
| 卡底、插图、边框、标题、说明、费用组成同一张卡 | `scripts/card-face.mjs`统一生成战斗/奖励、牌库及节点卡面，保留原有控件名和主题尺寸 |
| 不同场景复用同一卡牌绘制入口 | 战斗、牌库、商店、选卡和升级预览共用组件及资源解析，场景只保留交互/售罄/选择覆盖层 |
| 牌面数值来自卡牌当前状态 | 保留核心预览和既有中文表现层，图片资源不写死伤害、费用、升级说明 |
| 资源与卡牌逻辑分离 | 资源登记在主题，逻辑继续从data和Lua核心读取；替换已批准资源无需改战斗规则 |

原版代码能确认资源装配和渲染流程，不能据此恢复原画创作过程。本轮没有搬运原版贴图、字体或美术文件，也没有增加图片导入通道。

## 生产入口

1. 卡框/卡背/类型徽记继续使用[已有生产规范](CARD_PRODUCTION.md)和[共享资产](CARD_SHARED_ASSETS.md)，保留Image Editor可编辑稿和原有导出器；PNG仍仅用于离线审阅。
2. 本轮接通的卡图后端为原生图库图片ID。在`data/presentation/ui_theme.json`的`icon.cardPortraits`按真实卡牌ID登记`{ "id": 原生图片编号, "status": 验证状态 }`。没有登记的牌返回`placeholder-type-icon`；URL和图片路径不能作为运行时图片参数。
3. 现有`cleave`登记为`102012 / placeholder-native-icon`，用于打通既有样卡的装配入口，仍是占位，不表示精修插图完成。其他牌继续明确使用牌型占位；未批量制作卡图。
4. 执行`npm run build:ui`，由同一组件输出战斗、牌库模板及节点界面，再沿用原来的候选构建/MCP写副本路线。原生中文只有一套动态文字槽，卡面随宿主一起缩放和旋转。

复杂图元插图和肖像的既有实验没有在本轮被自动放行；原生ID接通不代表那些候选的质量、蒙版或多卡成本已通过。
