# 启动／选角主视觉：官方源控制变量与矩形管线

## 当前决定（2026-10-29）

Owner认可[480×270 STD3候选](../../art/characters/key-visual/traveler-geo/official-landscape-v1/README.md)的实际Lua离线视觉，并决定本次先采用官方画面，完成必要尺寸、加载和释放适配。只用于启动与选角，不扩大到战斗；本轮不重新构图、不生产其他角色。原创背景与进一步画质优化延期，不用追加实验阻挡接入。

当前产物不是已导入的游戏截图。官方GIL、真实ready、PC及实体安卓验收仍未执行。候选默认不启用，不把现有图库占位状态改成已通过。

## 为什么换路线

1. AI全身立绘＋自动色区三角拟合出现脸、发丝、白花和衣料碎片化。局部手修不能证明整体达到正式标准；两张旧图被Owner否决，不能沿用旧的“技术检查通过”来批准视觉。
2. 换干净官方荧原图控制变量：初始拟合在Lua导出前已经丢失五官和细黑线，说明不能只怪源图构图或导出。手修后的8084控件虽更连贯，仍失去官方神态和材质，不作为本轮正式路线。
3. 保持官方横幅构图不变，使用矩形合并直接还原像素，再经既有编辑器导出；脸和轮廓的保真更好。不是由AI猜画另一张脸。

未来原创设计仍须先参考已认可的官方/STS画面信息层级：一个清楚主体、适当留白、连续材质、少量环境。不得把这条要求变成复制对方角色、标志、界面或文案；也不随意堆碎石、复杂光效与无关细节。

## 固定工具与真实参数

- 矩形算法：[wwh177/miliastra-image-algorithm](https://github.com/wwh177/miliastra-image-algorithm/tree/fdc76f28393babb7b960e09014ee43db36575c03)，提交`fdc76f28393babb7b960e09014ee43db36575c03`。本次已获Owner限定云端离线执行许可。上游未提供LICENSE，本仓库不复制其实现；工具使用与输出内容权利分别记录。
- 既有Image Editor：`103025f9095d8089e3f9bf097f4d0c5fe039d546`，使用其`export_json/export_lua/export_png`及真实`read_drawing`，未重写渲染框架。
- 离线拟合环境：Python3.12.14、Pillow12.3.0、NumPy2.3.5；固定编辑器环境Pillow11.3.0。本机已有依赖，无额外安装/付费API。
- 输入：官方1200×675媒体镜像，直接一次LANCZOS缩到480×270，RGB、无裁切、无改色；准确来源和SHA随资产。
- `STD=3, bits=8, dynamic=true, m2=2, m3=3, r=2`；动态`t1=30,t2=12,flat=12`，三档容差3/6/9。不要混用参数名与最终控件预算。

### 可复验步骤

1. 核对原图与工具提交哈希；只按同一次LANCZOS生成输入。Pillow仿射BICUBIC一次缩小曾带来输入锯齿，不能把输入退化怪给压缩器。
2. 使用上游`estimate.py --input <已缩小RGB输入> --size 480x270 --lock-aspect --std 3 --dyn-std --bits 8 --geometry-check --preview`。若该版本单档CLI参数变化，以固定源码帮助为准，不猜参数或悄悄换版本。离线命令不应部署或启动客户端。
3. 原生候选重算通过已审核的`load_and_prepare → quantize → pack_auto`同参数调用，保留`(x,y,w,h,color24)`列表。要求块数13201、覆盖每像素一次、扫描顺序正确，重建PNG与冻结预览一致。不能从PNG反推并冒称取到了上次进程中的块列表。
4. 薄适配仅映射既有rectangle JSON：中心`x+w/2,y+h/2`，宽高原整数，XYZ旋转0，opacity1，zIndex保持扫描序；画布480×270。禁止偷偷把宽高减1去迎合离线栅格。
5. 固定编辑器`ImportRequest(sourceType='json',content=...)`后，以`ExportRequest(scene=...,giaGroupName='Official landscape STD3 rectangle probe')`调用完整导出。先确认完整Lua小于工具10MiB读入门禁，再使用`lua_scene.read_drawing`读取真实数据；只去编辑快照作诊断，比较完整/去快照绘图表相等。不能调用私有emitter绕过门禁。
6. 官方JSON与实际Lua分别重绘1×/2×，核对元素、RGB、坐标、顺序和PNG；源图→拟合→官方JSON→真实Lua四阶段分开报告。最后才做官方导入、同一设备基线和真实界面测量。

本资产保留块列表及可编辑JSON，因此复验数据映射/真实导出不需要重新运行未随仓库分发的拟合器。新增工具或不同来源的代码仍需按许可和执行权限确认，不能把本次许可扩展成任意程序自动执行。

## 实测取舍（全部为云端离线，非设备性能）

同一官方横幅，动态阈值，8bit颜色：

| 逻辑分辨率 / STD | 矩形数 | 相对各自缩小输入的RGB MAE | 单通道最大误差 |
|---|---:|---:|---:|
| 320×180 / 1 | 18820 | 1.124664 | 27 |
| 320×180 / 3 | 8519 | 3.399595 | 55 |
| 320×180 / 8 | 3250 | 8.522778 | 118 |
| 480×270 / 3（获认可） | 13201 | 3.578835 | 61 |

320三档合计墙钟8.570秒；480单档6.162秒。它们是计算及离线检查时间，不是游戏加载时间。480的眼线/轮廓更细，但高光/背景色块仍见；不能仅按MAE比较不同采样尺寸。对同一960×540源参考，320STD1与480STD3的MAE分别3.703749/4.570650，也不等于人审结论。

### 优化尝试与不采用原因

- 对获认可13201块按完全同色、整边相邻、相同跨度合并：减少0块。不能把L形色区直接并成长方形覆盖其他颜色。
- 同480×270/STD3仅把bits8改bits7：13121块，只省80块（0.606%）和560字节块编码，却改变大量像素。源MAE升至3.59708。收益不足，不替换已批准图，不迁移人审认可。
- Base85是二进制转文本编码，不是减少图元的绘图算法。此上游每块5字节用自定义Base64存7字符；逐5字节块改Base85仍需7字符，不能直接套通用节省比例。编码优化降低脚本文本/解析开销，不直接降低最终控件数或保证FPS。

## 已定位的导出坑

固定编辑器PNG把矩形右/下端点包含在polygon内，上游NumPy重建则是半开切片。单矩形w4/h3预期12像素，编辑器1×画20；4×预期192，画221。当前480候选对Python的1×23984、2×47968个差异都落在右/下边缘，无透明孔洞；JSON与Lua字段及各自编辑器PNG一致。没有通过改尺寸、改工具或放宽阈值隐藏差异。引擎真正的光栅规则须另验，不能把离线PNG当实机截图。

## 最小接入与性能门槛

- 当前13201控件，不能从字节大小反推出内存或手机帧率。上游旧电脑/华容道记录没有本项目同机证据；局部改两格颜色和每帧改整张图不是同一负载。
- 1280×720对应8/3等比缩放；其他画布居中contain。现有320×420竖槽不是横幅宿主，不能拉伸进去。布局/按钮/输入由UI接入工作协调。
- 用专用背景宿主，有界创建、失败停止、取消失效保护；静态完成后不持续重写每个图元。启动/选角之间按实际生命周期选择复用，进入战斗前释放，不让背景控件常驻战斗。
- 测同设备无背景基线、首次创建/显示、重复进入退出、取消中断、输入响应、残留控件和内存。PC与实体安卓分别记录；回调dt不是GPU耗时，没有实测不写“流畅”。
- 已提供资产级[窄生命周期组件](../../art/characters/key-visual/traveler-geo/official-landscape-v1/runtime/README.md)：默认每tick最多64个，完成前隐藏，取消失效及失败回收/显式重试；19项离线VM验证通过，13201条几何和颜色保持等价。默认207次tick不是设备耗时；主动release仍同步遍历，实际退出成本未测。组件尚未注册到正式UI构建，不能称接入完成。
- 尚未正式导入或启用；不改`heroSlots.id/status`把图库编号冒充图元组，也不把图片资产100001当模板索引。
