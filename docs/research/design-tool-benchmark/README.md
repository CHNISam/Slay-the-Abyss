# 游戏 UI 设计工具对照实验（TASK-95）

目的：寻找能独立作出高质量美术、交互与动效设计判断的模型/设计环境，**不以代码能跑代替视觉品位**。实验结果仅为方案选择依据，不直接批准千星原生接入、取代正式 QA 或阻塞 M4 非设计工程。

## 基准与可比性

- **MAP-v1 原始提示词（只读基准）**：[map-v1-prompt.md](map-v1-prompt.md)。2026-11-02 用户提供的 Google AI Studio 版完整原文，后续不得偷偷改词后仍称为同一实验组。
- **组内 A/B（强对照）**：在同一个工具、同一个模型、同一份原始提示词、同一项目快照及参考附件、相同会话起点与迭代/预算条件下，每次只改变一个变量（例如普通推理 vs Max）。
- **跨工具对照（弱对照）**：MAP-v1 明写“Google AI Studio Build”，不能原封不动要求 Figma Make/OpenDesign 在 AI Studio 内运行。未来须单独建立工具中性且完整归档的 MAP-v2，在所有平台仅替换最小执行入口；视觉需求、游戏规则和评审量表保持一致。MAP-v1 与 MAP-v2 **不合并成绩**；模型本身与工具外壳的效应不能拆解时，应如实标为“模型 × 平台”组合。
- 原始 MAP-v1 提到“最新 develop”而没有锁 SHA：**2026-11-02 两次已做测试的真实仓库快照未知**。未来每轮须事先固定 SHA，并保存所给附件的文件版本、成功访问清单。当前归档时 `develop` 的 SHA `6354f6328fd6b2b7c53a758dd9e470948d21efc1` **不是**历史两轮已核实使用的 SHA。
- 目标 1280×720，记录移动端尺寸与地图种子/节点状态；如不能统一真实 seed 或素材权限，说明不可比项，不作强因果结论。
- Skills 应记录“真实加载成功 / 未加载 / 未知”，不是提示词写了链接就视为生效。

## 逐次执行与取证（每次独立新会话）

1. 固定 prompt 版本（记录哈希）、项目 SHA、场景数据/截图与 Skills 可访问状态；记录平台、模型真实显示名与版本、推理档、温度/seed（若可控）、日期、账号档位和功能开关。
2. 首次产出保持同等时间/轮次/费用预算，不额外给某一组修正提示；分别归档首稿与相同次数迭代后的最终稿，避免挑选最佳样本冒充单次结果。
3. 保存 Preview/可导出源码链接、1280×720 截图、手机截图、关键交互录屏、实际加载成功/失败和用量。无法获取的字段写“未记录”，不得补猜。
4. 先匿名展示等场景截图做盲评，再看交互与技术可移植性；标注谁评价、日期及是否单人判断。建议每组至少 2–3 次独立运行后再讨论稳定性；目前仅有各 1 次用户报告。
5. 单项评分采用 0–5 分与文字依据。综合参考权重：**美术审美/世界观 40%**、**信息层级与可读性 20%**、**交互及动效 20%**、**规则与约束遵循 10%**、**千星落地适配性 10%**。可运行性、导出能力、许可证/成本、设备性能作为独立门槛，不用审美分抹平硬性不合格。
6. 如实区分用户报告、截图可复核、原型实测、Lua 证明、官方 PC 与实体手机证据；不把 Web Preview 当作游戏内已实现。仅在有实际产物时写 Go / No-Go / Conditional。
