# 卡组查看 Implementation Plan

**Goal:** 按 PR #19 的 `openDeck` 批准稿，在地图、战斗和节点查看永久卡组。

**Architecture:** GameUI 管理覆盖层和底层输入门禁；独立只读 DeckUI 将永久卡组副本填入原生六列 grid。原生模板复用批准稿卡牌结构，主题保存所有布局数值。规则、交易、发牌和随机数不变。

**Tech Stack:** Lua 5.3、原生客户端 grid/template、现有 Node/Fengari 测试与 MCP 副本编译。

1. 为真实导入树和 GameUI 夹具补行为测试：入口、滚动复用、同名不同 UID、升级/X 费用/成长文案、底层命令隔离、重复开关、结果/反馈门禁。
2. 提取 `layout.deckView` 主题常数并生成模板、覆盖层和共享入口；build-ui 输出模板，candidate 构建器先写模板再写界面。
3. 实现 DeckUI 的只读快照与回调刷新；官方未规定 callback index 基值，先以单项回调读实际基值，下一 update 刷新全部卡牌，兼容延迟和复用回调。
4. GameUI 打开时取消拖牌，禁用底层控制器命令但保留其画面；关闭恢复对应模式。反馈忙、菜单与结算拒绝打开，宿主换局/结果自动关闭。
5. 跑针对性测试、完整 `npm run check`，生成离线候选并做 Lua/客户端静态检查；不启动原神，不勾设备预览或实机验收。交主线程复审、CI 后合并。

API 依据：本机 MCP knowledge `official/guide/mhtakr07vej4.md` 的 ClientUIGridScrollerControl（RefreshItems / scrollProgress）；`official/guide/mhfkrr0i7gds.md` 的滚动复用；`notes/client-lua.zh-CN.md` 的 grid/template 格式。没有新增视觉方向。
