# 同档原生 3D 战斗实验

**任务：** TASK-102；用户明确授权独立实验，正式游戏不迁移。

**目标：** 一次导入一个 GIL，在游戏内完成六类手动和连续对比。

**设计：** 沿用正式 Lua 卡牌规则、卡牌和战斗 UI。额外实验菜单覆盖在同一候选上；2D 继续使用正式表现，3D 用透明战斗背景展示官方复杂造物。Lua 只发动作指令，节点图创建/隐藏模型并执行原生技能；技能不放命中盒，原生生命和 AI 不参与规则结算。不可用实验显示明确原因。

**选择：** 优先采用官方复杂造物、技能动画和已有 Genshin-TS 工具。普通怪物原生 AI 难以精确受控；自制骨骼或 3D 卡牌会扩大维护工作，只有官方能力满足时采用。

**步骤：**
1. 核对实际工具资源、官方知识和社区已验证复杂造物样例，记录可调用动画及缺项。
2. 复用现有战斗驱动，建立隔离实验菜单、命令和回执、固定种子自动场景、屏内日志及 OnUpdate 间隔统计。错误限制在单项实验内。
3. 创建原生模型/技能/决策与服务端信号桥，构建完整候选。写入和读回逐项核验；测试不得把发送指令当成动作播放成功。
4. 针对菜单切换、真实规则一致、停止/重置、失败恢复和性能配对运行验证；独立复审，提交代码和结果 PR。
5. 官方导入、当前候选 ready、动画视觉效果和手机 GPU/内存均单独列证据状态。无本轮输入窗口继续离线工作，交付前请求具体窗口（如确需）。

**验收边界：** OnUpdate 间隔只是客户端脚本帧间隔；没有 API 的 GPU 帧时间、内存和官方负载显示 UNAVAILABLE，手机未测显示 UNVERIFIED。死亡 clip 缺失则明确区分模型移除与死亡动画。正式迁移只在关键能力及手机证据达到要求后建议。

**同任务追加：** 用户要求在真实手牌的最小归位场景对照 `game.Tween()` / `TweenSequence()` 与原有 OnUpdate 插值。仅在实验候选变换卡牌视图副本，统计Lua调用量并验证中断、拖拽、命中区、销毁；流畅度仍需原生客户端。若生命周期代码和限制抵消收益，保留有界实验结果、不接入正式路径，不另建任务或重复验证3D桥接。

**候选范围扩展：** 复用固定上游shape工具做一个24部件六焰核、现有Run奖励事务做6条库的原生三选一、官方timed命中特效与纹理底板降级样张；枚举完整四幕67个规则定义并单列阶段状态。复用85472c95副本增装，保持原桥/Tween，不改正式ID/数值。底板未证明当前战斗减负则不推荐正式替换；动作入口探针不取消原失败判定。实现、证据和取舍统一记录在 experiments/native-3d-lab/EXPANSION-RESULTS.md。
