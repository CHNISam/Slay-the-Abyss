# StS1 W1 Evidence and Unknown State Implementation Plan

**Goal:** Begin W1 with executable, independent map evidence and the verified basic unknown-room transition contract. W1 remains open until generation, entry/UI/restore, golden diffs and property tests pass.

**Architecture:** Keep the current game reachable while building an explicit failing parity gate against actual external Oracle output. A pure Lua probability reducer accepts an injected roll; it cannot claim original RNG, special-relic or room-entry parity. Do not approximate the unverified map algorithm or silently replace the approved presentation.

**Tech Stack:** Existing Node test runner, actual Lua through Fengari, Oracle release executable used only as a black box.

## Slice 1 — Independent evidence

- Add `scripts/sts1-map-evidence.mjs` and `tests/sts1-map-evidence.test.mjs`.
- First test canonicalization, malformed input, missing/extra/type/edge differences, and reject false greens including missing fixtures and unsupported 64-bit seeds.
- Capture the 12 requested seeds from the pinned Oracle with explicit `--a0`; retain process failures as failures, never expected maps.
- Compare actual `abyss_map.generate` output. The initial gate must fail for the existing three-column/Boss-15 implementation.

## Slice 2 — Verified basic unknown-room reducer

- Add `src/lua/abyss_unknown.lua`, `tests/sts1/unknown.lua` and a Node bridge for the supplied nine vectors.
- First observe a missing-module failure, then implement one injected roll, cumulative Monster→Shop→Treasure→Event thresholds, exact percentage arithmetic and hit-reset/miss-increment.
- Test equality boundaries, cumulative probability above one, sequences, malformed snapshots, alias isolation and invalid-input atomicity.
- Keep source-specific RNG, previous/next shops, special relics and actual entry integration explicitly unimplemented. They must not be guessed from the basic vectors.

## Slice 3 — Verification and review

- Record evidence and remaining deltas in `docs/rules/sts1-rule-matrix.csv` and `docs/rules/W1.md`.
- Run targeted tests, full existing quality checks, and the independent parity gate. Distinguish code checks PASS from map parity FAIL.
- Keep TASK-12.4 In Progress and its acceptance criteria unchecked while W1 lacks proof. Do not read/start W2 before W1 acceptance.
- Submit the tested slice through a PR; the full W1 gate remains a separate unmet condition. Platform compile, test-copy import and real-client verification are not performed by these offline checks.
