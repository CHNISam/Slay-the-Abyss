# 美术加载与试玩交付修复计划

目标：最新 develop 的已有美术实际显示，加载有反馈，切页与退出不集中调用数千次原生销毁。原工作区及正式分支不修改。

基线：origin/develop 1bfca626（PR361），已再次 fetch 确认。授权：用户允许自行优化性能与加载体验。

证据：本轮日志80/82/83均按构建标识匹配。Image不支持raycastTarget；背景第二帧已有64控件，但13201个全部完成前隐藏；退出发生大量生命周期内Destroy错误。v3证明模块及逐帧入口实际执行。

方案：

1. 恢复已批准原画质数据，背景13201图元逐项一致，头像/战斗图保留原始4822/4315图元。V4降采样虽然加快加载，但用户实机否决其马赛克画质，不进入交付默认值。
2. 对照用户指定的wwh177/miliastra-image-algorithm原始render.lua：隐藏且inactive的分组中创建，按时间预算推进，完成后分帧激活。仅对已验证的轴对齐矩形复用模板默认变换，容器不超过60子节点，不复制上游未授权源码。
3. 背景/肖像切页隐藏并保留，避免同步销毁；退出完全交给引擎。加载展示进度。选角隐藏背后菜单、修正头像/文字重叠、给右侧主立绘单独宿主并保留宽高比，移除元素按钮的礼物占位。颜色/尺寸复用主题与现有框架。
4. 正式构建单次批量写入源码、完整读回核对；诊断包与修复候选明确分开。

2026-10-30用户最新范围：自定义卡面插画可暂不启用，优先背景和选角。正式候选默认关闭动态卡图（构建参数明确no-ready-card-art），源资产保留；不再为了卡图换牌缓存拖延本轮交付。
