# TASK-3.3 全平台主动退出

用户实机指出，手机没有 Esc，电脑玩家也不应靠记住 Esc 才能退出。此前宿主只在胜负结果页提供结束结算，正在战斗或浏览节点时缺少入口。

## 已确定的行为

- 所有页面共用可点击、可触摸的“退出本局”，包括菜单、地图、战斗、奖励、节点和牌库。位置及尺寸来自共享主题；复用批准稿的颜色、文字和按钮四态。
- 点击后显示确认层，说明本局进度不会保留、结束后进入平台结算；“继续游戏”取消，“退出并结算”确认。
- 确认层冻结客户端游玩更新与演出，阻断底层卡牌、奖励、地图和交易。取消保留同一 Run、地图、牌库位置和未播放完的演出，恢复游玩。
- 退出无需等待战斗结束或演出播完。游玩中主动退出走已有 ABYSS_LOSE 正式结算链路；已有胜利结果保留胜利，不伪造战斗 HP 或奖励。
- 请求一次提交；回调失败保持确认层并可重试或取消。已提交后阻断继续游玩和重复提交，等待平台结算页。
- 触摸/鼠标确认绑定自己的按下与抬起；关闭重开或尺寸变化使旧手势失效。Esc 仍是平台能力，界面操作不依赖它。

## 平台边界

本机官方客户端 Lua API 没有打开原生暂停菜单或直接离开关卡的方法。官方课程允许中途结算；复用现有服务端结算图设置胜败并调用 settleStage。进入平台结算后，玩家使用其“离开”按钮。

不调用 PauseLevelTime：该 API 不暂停 OnUpdate，且确认后需要正常处理服务端结算信号。本次冻结的是该单人卡牌游戏的宿主更新。

## 验证

先用真实生成控件及真实宿主回归复现缺少入口，再实现交互；检查取消、底层隔离、反馈中退出、牌库/节点、重复确认、失败重试、旧手势、尺寸变化和已胜利离开。布局测试核安全区、通知避让及控件容量。

本地检查、编译写入副本、官方导入和实机操作分别取证。手机真实触控、平台结算后的离开仍需新版副本实测；不能用当前旧副本的失败结算确认替代。
