# M1 基础战斗演出（TASK-29）

基于 develop `2ff1588`；只优化表现，沿用 PR #19 的岩金/钢蓝主题和 C 档点选。规则、数值、随机数和回合仍由同步核心结算，未引入异步战斗系统或新依赖。

## 已实现

- 真实攻击牌飞向目标，随后命中闪光、受击位移、实际伤害/格挡飘字、HP 与残影；格挡牌显示蓝盾，能力/状态用对应状态图标、语义色和层数提示。
- 敌方回合横幅 → 当前行动者及其意图高亮 → 每段攻击/格挡/施法 → 下一敌人 → 我方回合横幅。中毒和荆棘显示状态名、来源日志；死亡淡出后才进入胜负横幅及结果页。
- 玩家实际失血才轻微抖屏；完全格挡不抖屏。普通出牌约 0.4 秒恢复输入，0.6 秒飘字与 HP 残影可并行收尾。多段普通伤害每段 0.2 秒、敌人意图间隔 0.45 秒、回合横幅 0.9 秒，全部取现有 `Theme.motion`。
- `abyss_events` 保存与每个事件对应的轻量视图快照；只复制运行字段，规则表/意图等只读定义共享。`abyss_feedback` 只操作原生控件。UI 消费成功命令新增事件一次，完成后清空已消费帧并保留事件表身份，避免整场累计。
- 表现故障不回滚或重放已提交的规则，恢复最终画面与输入；音效故障单独隔离。替换战斗会取消旧队列与残留效果。宿主只在队列结束后切奖励/失败页面。

## 平台降级与待验

| 项目 | M1 方案与边界 |
|---|---|
| 原生动画 | 使用现有 OnUpdate 与控件 setter 插值，避免依赖未经本候选验证的 Tween 完成回调；最长单帧只推进一个可见步骤，不跳过整回合。没有改主题时长。 |
| 飞牌 | 复用批准卡面尺寸、类型图标/底色和名称的简化飞牌；0.2 秒直接取 `motion.base`，原型文档 0.18 秒没有另设一套常量。完整卡面飞牌、角色动作和岩粒子细化留 TASK-4。 |
| 受击位移 | 幅度取现有 `space.s`；抖屏取 `motion.shakeAmplitude`。数字、状态图标、盾牌复用已有图库。 |
| 状态 | 本地实现状态图标脉冲及已有状态文字层数；永久图标阵列与多状态拥挤处理仍由 TASK-4 打磨。 |
| 控件规模 | 完整游戏静态树 1154 个控件，最大直接子项 50（MCP 上限 60）；仅新增 32 个固定控件，不随事件分配控件。实际帧率和手机/主机安全区未验。 |
| 音效 | `Theme.sound` 使用平台目录中的 UI 基础音候选；`game.PlayAudio2D` 接线并输出 `ABYSS_AUDIO`。目录与已有工具实测说明不能代替本候选实际出声与听感验收。 |

## 验证与交接

本地回归：攻击/格挡/敌方回合、多段、多敌、群体、能力/减益、中毒、反伤、击杀、胜负与宿主过渡；6 个种子、最多 120 条真实命令逐步比较直接规则与 UI 命令的运行状态和 RNG；消费帧释放；重复点击、故障注入、音效不可用、切局取消和空闲残留清理。规则原子性旧测试继续保留，新增状态/格挡事件的预期顺序同步更新。

本地、CI、平台静态检查、存档导入和真实试玩分别记录；TASK-29 保持 In Progress，直到实机验收完成。原数值候选由现有完整游戏入口进入，不添加调试战斗或改变初始牌组。

实机衔接 TASK-3.2 / TASK-3：记录同一 SHA、候选 hash、官方新测试存档编号、runId、屏幕尺寸及本轮截图/日志或录像。先真实出攻击牌、格挡牌、结束回合，观察整个回放，再补多敌、多段、状态和胜负。日志以 `ABYSS_FEEDBACK <kind> source=… target=… amount=…` 对照核心结果；音效另以 `ABYSS_AUDIO` 与实际录音验证。不得拿本地替身或旧 v6 实机截图替代。

M4 TASK-4 只承接更精细的岩元素技能、动作/命中/死亡效果、正式音效选择与节奏、多设备预览和性能/体验验收；不重复实现本次队列及基础反馈。
