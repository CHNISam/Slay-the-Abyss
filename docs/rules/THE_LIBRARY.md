# 第二幕图书馆（The Library）

固定事实来源为 `aeubanks/sts@319009d5df0a82d9fb0f23cc22322286c6a87ec0`。`tests/fixtures/library-source-contract.json` 记录16份相关源文件的Git blob、原始字节SHA256及来源链接；主要事件 blob 为 `185c2916997d5b68539bc8208e5fc47e0d724484`。这是已重新核对Git对象的反编译镜像，不等于原版PC二进制或原神实机验收；不在产品中复制Java实现。

- 入口只有阅读、睡觉，无离开。睡觉缓存进入时最大生命的 `round(float32(float32(maxHP)*0.33f))`；50→17、75→25、80→26。缓存不因之后的果汁/最大生命变化重算。调用已有 `Run.heal`，保留满血上限、Mark of the Bloom禁止治疗；不是篝火，不加皇家枕头。当前非战斗状态不保留战斗Power治疗修正。
- 阅读每次尝试都按 `rollRarity`、`getCard` 顺序消耗同一 `cardRng`。重复源cardID会重新抽稀有度及身份，接受恰好20个不同身份。已有牌组不排除来源。保持当前职业完整、源顺序的reward桶；不使用反转的src桶、商店桶、跨色奖励或缩减卡池。
- 读取继承的稀有度偏移，不修改它。普通事件房间基础稀有阈值3、罕见上限40；N'loth's Gift先把稀有阈值乘3，随后加37得到46。没有普通战斗奖励的保底更新、升级float、卡数遗物及棱彩碎片跨色分支。独立Python工具从固定注册/HashMap顺序及既有独立整数RNG解释生成17份向量，含每次重复尝试、primitive拒绝及完整RNG继续状态；不是运行Lua后回填预期。
- 每个被接受的私有预览只调用一次现有 `onPreviewObtainCard`，不分配永久UID，不付陶瓷鱼金币。源 `addToBottom` 在列表前插，故显示顺序与接受生成顺序相反。
- 源四参grid重载内部 `canCancel=true`，但普通事件没有取消按钮，事件也没有跳过分支。原生既有分页控件以私有 `offerToken` 选择，不冒充永久牌UID；只显示真实20张，不能返回/跳过。隐藏、重绘、缩放、分页均不重抽。手势绑定事件/节点/运行/控件/视图/页/选择及offer epoch、实体、身份、升级值，失效后不能复活。
- 选择时按源 `makeCopy` 创建全新基础牌，再调用 `Run.obtainCard` 的规范定义、能力、UID、获得钩子及永久入牌组事务；不是把升级预览直接插入牌组。已有毒蛋在预览和实际获得分别升级独立对象，获得陶瓷鱼金币仅一次。选择和睡觉都停留结果页，再按离开才结束节点回图。

## 明确边界

当前完整Run目录为四个映射源职业，历史 `Profile.prepare` 组件和原创V4没有可假定的完整源职业映射；其阅读禁用并明确说明，睡觉仍可用。这是实现边界，不是原版职业规则。共享遗物钩子目前实现毒蛋，但没有熔融蛋/冰冻蛋的预览及获得钩子；强制持有它们时阅读原子拒绝，不能假造升级。现有支持遗物没有会修改牌组的 `onMasterDeckChange` 后置钩子，沿用唯一永久获得owner，不另造重复插入/回调框架。

原版阅读结果文案选择使用全局美容 `MathUtils.random(2)`，本实现使用固定本地阅读文案，不污染任何有种子玩法流；此项是文案降级，不是随机重放一致声明。MathUtils正数快速round的公开libGDX实现已核对：本项目有符号32位正最大生命乘0.33f落在其int转换范围内，double偏移等价于上述正数取整；未借此声称确认原游戏的依赖版本。

所有公开事件命令仍由 `Nodes → Run.transaction` 原子发布。缺失定义/能力、预览异常、后期获得失败、金币/UID边界不缩池、不重抽、不部分付费；保留所有原owner身份及RNG继续状态。
