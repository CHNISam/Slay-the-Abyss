# 第三幕事件战斗与终幕资格离线接线

本轮按固定来源 `319009d5df0a82d9fb0f23cc22322286c6a87ec0` 补齐心灵绽放、神秘球体及绽放印记，并接入现有第三幕事件池、Nodes、Run 与事件界面。三职业历史胜利资格使用独立 EndingHistory owner。本文记录本地受控证据，不认证自然四职业通关、原生导入或完整 M3。

## 已接行为

- 神秘球体在进入事件时构造双 Orb Walker，保留四次 HP RNG 消耗；离开不初始化 AI。选择战斗后按源先准备45–55金币和 screenless RARE，再进入战斗。
- 心灵绽放按一次 misc Long 驱动 Java shuffle 选择第一幕首领，准备50金币和普通 RARE。Boss actor 仍禁止烟雾弹，但房间仍是事件房，不消费地图遭遇队列、不触发第三幕终局。
- 两事件胜利均保留预置金币/稀有遗物，依次尝试药水、生成一组卡牌奖励。领取只提交既定奖励。双球体逃跑会执行战后治疗钩子和药水尝试，丢弃所有奖励，不生成卡牌或增加胜场。
- 心灵绽放的全部升级、999金币与两张平庸、治疗后疑惧均使用真实永久库存 API。获得印记后，共享治疗、营地/神职人员预览和实际治疗、战后治疗均受封禁；最大生命增加和敌人治疗保留原规则。
- Host 在创建地图前读取独立的三职业胜利历史；仅合资格的普通、非种子/非 Daily/非 Trial 第51层结局写入本职业的 true-only 增量。没有持久提供器时不声称持久解锁。

## 实际验证

`tests/lua/event_combat_bridge.lua` 使用真实 Run、Nodes、Combat、地图和来源队列。受控事件身份、消耗后的 RARE 队列及手动置零敌人生命仅用于检验边界，不作为自然流程证据。

1. 原实现缺少事件构造 API，回归明确失败；接线后通过。
2. 烟雾弹漏战后治疗，回归明确失败；补结束钩子及流同步后通过。
3. 独立审查发现事件胜利后下一普通房间残留旧 owner；连续真实 Nodes 进入回归先失败，补传播删除后通过。
4. 永久牌同步晚抛错会泄露已经修改的牌；注入故障后完整图比较先失败，扩大结束快照保护后通过，原牌/战斗别名保持，可重试成功。
5. 烟雾弹候选表删除 owner 未传播回原 Run；新增检查先失败，显式同步可删除字段后通过。

扩展事件桥最后一轮通过用时12.350秒。第一批固定来源合同及桥 Node 7/7通过；印记、球体、历史及已有第三幕组合 Node 12/12通过。数据构建、3562控件 UI 构建、内容校验、JS语法和Backlog门禁通过。依赖检查198模块/1148边；Luacheck零新增、84条原历史告警、358项职责度量及原复杂度限制保持。NodeUI 新增两行名称/正文使既有13条告警及其引用行号统一偏移两行，没有增加豁免。
