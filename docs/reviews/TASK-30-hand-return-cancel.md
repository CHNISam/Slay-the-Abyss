## 已复现的原因

当前工程已有社区反编译输入迁移，见[来源与映射](TASK-30-source-input-port.md)。Lua不能直接运行LibGDX的Java输入及渲染代码。本轮修正既有迁移与原生布局之间的不匹配：

- `placeDraggedCard`进入目标模式后强制`x=0`，不论原来抓的是哪一张，都会突然覆盖中央手牌。现有单卡用例本来就在中央，无法检出这种跳位。
- 原版取消线换算为接近屏幕底边的位置，而本项目的牌排在其上方。返回可见手牌行不会取消。无目标牌在0.4秒内回拖还会进入`carry`，把本来要放回的牌重新选中。
- 抓牌及取消时未清空旧悬停归属，可能继续保留另一张牌的升起状态。

这些是本地稳定复现，不等于已证明用户截图中所有原生事件派发路径都由上述原因导致；仍需同候选实测。

目标模式保留抓起牌的横向位置，底部高度和安全区仍沿用现有布局。手势第一次进入战场后，回到主题定义的可见手牌行即取消，优先于短拖保留选牌；原版底边、右键、同牌再次点选取消继续保留。抓牌和回拖取消同时清空悬停，原有触点、卡UID、战斗、回合及一次提交保护保留。
