## 契约与范围

`Map.restore` 只恢复导航图；同局卡组、遗物、药水和待处理节点仍由原来的 `Run` 持有。
本切片保护恢复后的公共 API 组合，不新增完整 Run 序列化，也不要求退出关卡后续玩。
已有单模块地图/库存测试之外，新增恢复发生在奖励、购买、营地和宝箱事务之间的组合边界。

测试使用真实 Map/Nodes/Run 和原始战斗内容。固定 seed 36 的首战由原始卡组公开出牌/结束回合命令获胜；
之后按实际可达路线进入事件、商店、营地、固定宝箱和下一场精英战。
唯一数据表改动是起始金币设为 1000，以覆盖购卡、购遗物和删牌；另通过 `Run.obtainPotion` 预置三瓶药水，并在首战实际使用中间槽的能量药水形成稀疏槽位。
这些药水是显式测试夹具，不代表自然获取链；价格与效果不改，未编造经济或原版概率结论。

## 新增 5 组可执行回归

1. 待领奖时恢复地图，保持导航锁和原待处理节点归属；领取一次后仅新增一个永久 UID，重复领取拒绝，完成后才允许下一节点。
2. 已购买卡牌和 Anchor 的商店内，8 种非法快照安全拒绝且输入、循环/别名结构、Run 与当前地图均不变；有效快照仍可继续，下一商店不再出售已拥有遗物。
3. 合法但落后一层的旧快照不能重新进入已完成商店或重复消费；正确快照继续后补瓶填入物理槽 2，其他槽不移动。
4. 经过恢复的删牌、升级和遗物获取保留永久 UID 及状态；下一战包含正确卡牌/升级多重集，战斗实例不与永久牌组共享对象，Anchor 真正生效，稀疏药水槽不丢失。
5. 同值边列表的输入别名可以恢复，但输出边列表彼此独立且不引用输入，修改一个恢复边不会污染其他节点、快照或原地图。

战斗 UID 是独立的临时命名空间；测试不错误要求它等于永久 UID，而是分别验证永久 UID 稳定及战斗卡牌内容、升级、实例独立性。
