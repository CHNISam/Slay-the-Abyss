# Neow 正式入口与同会话历史

固定源与奖励规则沿用 `docs/rules/NEOW.md` 及其十五份文件身份，不改变奖励定义、候选池、概率、随机调用或旧源码正文哈希。

`Nodes.beginNeow` 只接受尚未走图的新 Run/Map，在地图之外建立开局事件；保持第0层地图、空路径、所有房间/RNG/遗物队列不变，不调用房间进入钩子。事件选项、奖励卡、单独药水领取与永久牌选择使用现有生成 NodeUI。双选先保存第一张 UID，第二张确认后依原顺序提交；升级继续使用统一卡面前后预览。每次重绘、换owner、隐藏和缩放都会使旧操作失效。完成结果页后原 Map 第一条合法路线恢复。

正式 `GameUI.start` 在 Run/Map 成功创建后尝试恩赐，原序章只负责覆盖，结束或跳过后显示开局事件。主界面的默认 Start 手柄焦点保留；战斗速度 setter 拒绝所有非菜单和模态上下文，结果页隐藏速度按钮，避免与结算按钮重叠。

历史接口为 `platform.readNeowHistory(character)`，返回 `{bossCount=0|1}` 的真实平台读取结果。失败、缺失、非法值或显式 `known=false` 均保持未知。没有默认0/1，也不建立持久化文件。同一 host 内由实际结局或已接受的明确放弃记录上一局：胜利写1；死亡/放弃按真实 floor>=16 写1，否则写0，分角色覆盖而非累计。新 host 没有平台读取就仍然未知。本环境尚无原神跨局历史能力证据，所以首次未知时保留可玩的原开局资源，并在地图明确显示“开局恩赐暂不可用：未取得上一局历史”。这不是完整跨会话 Neow 验收。

另接现代宝箱的既有蓝钥匙页脚：严格识别已打开的 source chest 与完整奖励形状，保留旧 Map/Run/路径/楼层/代次校验，以长度编码的完整奖励摘要绑定旧按钮。初始缺定义的基础遗物可以舍弃换钥匙，先前声明可用但随后内容丢失会拒绝。选择只消耗关联基础遗物/蓝钥匙，金币和套娃额外遗物保留独立待领；源 token 拒绝 metatable、额外字段和上下文漂移。旧单遗物入口仍有原独立路径，不放宽匹配门禁。

验证：history 4组、生成节点UI 8组、真实生成 GameUI 5组、source token与多奖励6组；旧owner初始化、序章10组、source宝箱4组。GameUI 的死亡→下一次mini来自实际 Run.endTurn 死亡，测试中的历史provider和套娃/缺定义输入均明确为夹具，不能冒充自然账号解锁或原生客户端证据。所有Lua夹具保留30秒预算。新核心模块与Nodes/GameUI固定Luacheck零诊断，NodeUI仅原有诊断移位；架构增量需将 `abyss_neow_history`、`abyss_treasure_source` 分类为core。

没有官方导入、键鼠操作、客户端日志、同候选截图或跨会话历史验收。
