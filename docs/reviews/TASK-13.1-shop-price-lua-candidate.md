## 数值与接口边界

- 只支持价格流水线所需的非负binary32：零，或 `[2^-32,256]`。拒绝负数、NaN、无穷、非数和越界值；不提供通用浮点库或次正规数支持。
- 按2的整数幂精确缩放至24位有效数，以最近值、恰好半值取偶数舍入，再精确缩回。binary32乘积最多48位有效数，可由binary64精确承载。中间量使用浮点，整数有效数不超过2^24，不依赖64位整数、位移、`string.pack`、`frexp`或对数，因此不依赖Fengari与原生Lua整数宽度相同。
- 延续JS候选的A0稀有度/颜色、首次上架/补货及逐次折扣顺序；会员卡现有报价仅支持整数0..198。未知字段、非法标志和无效组合拒绝；Lua表不接受元表。Lua的nil表示字段缺失，没有JS显式null与缺失字段的区别。
- uint24映射仅是有条件的依赖网格算术，不实现merchantRng，不消耗随机流；原版库存、遗物触发和交易资源账本尚未接入。

## 验证

新增Node测试复用项目既有 `runLua`，正式执行器仍是Fengari。覆盖原JS候选的价格/输入契约、上下端点、480个逐指数半ULP边界、4096组JS差分报价及4096组网格映射、全部199个现有报价。差分分为4批，每批1024组，沿用15秒执行上限。

云端现有 `liblua5.4.so.0` 已通过ctypes实际执行同一测试生成的Lua代码；本地仅替换测试运行器，不替换候选或断言。9/9组通过，差分每批约33–41毫秒；JS参考测试62/62通过。缺少Fengari依赖，本地正式Fengari命令尚不能运行，不宣称完整 `npm run check` 或Lua5.3/Fengari通过；由远端当前提交CI补验，不安装依赖绕过限制。

八种故意错误均被测试识别：半值一律向上、漏操作数规范化、double区间映射、首次取整改round、特价改round、折扣合并取整、补货提前截断、排除可达上端点；恢复原实现后9组再次通过。
