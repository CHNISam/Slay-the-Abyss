# 反复召唤后的敌人显示与输入

核心保留死亡怪物及原编队位置，Leader多次Rally和Collector反复重建TorchHead后，真实存活敌人的数组下标会超过5。原界面只读取前5项，因而漏掉首领及新召唤；本修复只改变呈现映射，不删除尸体、不改变战斗数组、AI或随机流。

`abyss_battle_enemy_view`集中生成最多5个显示槽，保留每项真实数组下标、ID及actor引用。存活敌人优先；反馈期间只在空余容量内保留尚未完成的死亡或逃跑演员。HP、意图、状态帮助、点选、药水选敌、拖牌准星和命中反馈共用该映射及主题坐标。发给核心的目标始终是真实数组下标。

按下时记录真实actor和显示槽；抬起、迟到Click或长按帮助完成前重查同一槽的归属，旧输入不能跟随槽位的新演员。控件换演员时清除旧浮字、护盾、死亡缩放等瞬态，避免尸体演出污染继承控件的活怪。

离线回归`tests/lua/summon_enemy_ui.lua`从真实Host/BattleUI及Combat入口，运行源AI的Leader多轮Rally、Collector反复TorchHead死亡/复活，直至保留数组超过5项，覆盖：全部活怪HP/意图/状态帮助、真实目标点选及反馈、拖拽准星和落点、同回合陈旧portrait/intent触摸、死亡后换槽的可见性及姿态。初始漏显示已证红；补充死亡姿态断言也先红后绿。原手势死亡用例保留物理释放坐标、HP/能量断言，改为读取压缩后的存活控件。

验证：召唤5组、原手势11组、操作手势8组、状态帮助8组、卡牌反馈10组、反馈事件3组、反馈动效17组、盗贼反馈2组通过，保持默认超时串行运行。架构132模块/652边通过，新增模块固定Luacheck零诊断。旧药水帮助用例的目录断言在本基线不认识新增EntropicBrew，前两组帮助/长按通过；该旧目录断言由集成线程单独校准，本片不改。
