# TASK-15.14 · 大型酸液运行时矩阵的夹具成本

## 合后失败与根因

PR153合入 `92c7627793cac6e9762d809ab09a610bbf883b82` 后，旧Windows runner的 [Quality run40057266468](https://github.com/CHNISam/Slay-the-Abyss/actions/runs/40057266468) / job120762884103 在 `acid_slime_l.lua` 的30000ms门禁超时。完整日志显示JS926通过/0失败/118跳过、数据校验通过；Lua前23组均通过，尚未完成第24组2600情形矩阵，后5组未执行。没有把超时归类为断言失败，也不把合前另一机器通过当作此机器闭环。

矩阵每个情形原先都以完整Data执行Combat.new。其实现为隔离运行状态而深复制rules、全部cards/enemies/statuses，每例575个固定目录表，2600例合计1,495,000表。最初原生Lua5.4计时中，矩阵1.314827秒，Combat.new占1.112738秒（84.6%）。热点是反复复制不参与本矩阵的定义，不是AI死循环。
