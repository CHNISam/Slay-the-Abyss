### 可用文案草稿（最终上线前须用实际功能复核）

- **名称：** 杀戮深渊
- **一句话：** 选路线、构筑卡组，在深渊中挑战最终首领。
- **简介：** 一款单人回合制卡牌构筑冒险。在多层分支地图中选择前进路线，通过战斗获得卡牌与资源，利用营地、商店和遗物完善构筑，最终挑战首领。每次选择都会影响接下来的战斗。
- **操作：** 以真机验证过的输入方式填写，暂不虚构按键；对应卡牌选择、目标选择、结束回合、地图选路和重开。
- **原创性：** 不能声称原创玩法机制、原创数值；重点核查卡牌文案、美术、命名、图标、UI、敌人形象、营销话术是否有未经许可的复制。平台官方素材使用遵循平台规则。

## 3. 发布前关口（TASK-19）

同一候选版本依次取得以下**不同类型**的证据，不能用「构建通过」冒充「游戏里可玩」：

1. **代码和内容：** 战士牌组真实可用，15 层分支与 7 类节点起效，资源跨节点保留，Boss 胜利/失败/重开正常；未实现部分如实记录。
2. **平台：** MCP 编译通过、导入到存档副本、在游戏内可玩分别出具结果；`MILIASTRA_ALLOW_LIVE_WRITE=0` 保持安全；更新后重新试玩候选。
3. **账号与展示：** 奇匠等级、外显文本、语言包上传校验、封面/图片、预览信息及所有必填约束通过。
4. **合法合规：** 列明来源、许可/限制，去除他人程序、存档、专属卡牌文案、美术与商标等复制内容；具体合规边界对照最新守则。
5. **发布：** 赛事报名勾选路径在真实 7.1 界面可见；确认不会误选其他赛事或「先行体验」；具有取消/复查机制。
6. **证据包：** 封面预览、完整试玩录像/日志、风险检查/负载报告（若适用）、候选版本提交 SHA、元数据字段清单、最终人工确认记录。

## 4. 2026-10-30 人工正式投稿 SOP（TASK-6）

**必须在 TASK-19 的发布候选验收完成、人工同意发布后执行。**

1. 核对游戏中 GUID、存档、作品名、目标候选内容一致，确保不是旧空白关卡；用真实客户端完成最后一次试玩。
2. 在「已上传」的目标作品，确认「预览信息」和「图片资产」全部填写并预览正确；填入最终标题、简介、玩法说明、标签与素材。
3. 根据当天真实 UI 进入正式**首次发布**流程；定位 **「赛事报名」**，明确选中 **「千星之约·奇域创作大赛」**。若找不到/不可选，**立即停止，不要先无赛事发布**。
4. 检查最终确认页显示的作品 GUID、赛事、账号、可见性、提交不可更换等关键信息；谨慎点击最终发布/投稿。
5. **截图/记录发布成功及赛事报名成功的结果**；在赛事中心或官方赛事活动页面核对这件作品确实列在本人参赛记录（平台提供相关入口时）。**仅显示「可发布」不算成功；仅显示已发布也不自动等于成功报名。**
6. 记录官方可访问作品 ID/GUID、完成时间（UTC+8）、证明截图、发布候选 Git commit SHA、是否审核/可游玩、真实试玩反馈与是否更新。
7. **真实发布成功且证据齐全以后**，才由 TASK-20 的发布流程生成 `v0.1.0` tag / CHANGELOG，不为日期空打版本。
8. 若发布失败，先保存报错、界面、当前作品状态，判断是否已消耗投稿次数；**不能未经核实重复提交**。
