# CI下载控制

用户2026-10-26明确：流量控制是最高优先级，同时保持简单，不引入复杂监控系统。TASK-60跟踪交付。

只做三件事：

1. checkout保存并推进`refs/ci/previous`和`refs/ci/current`，origin用set-url更新，不再删除remote后只fetch到FETCH_HEAD。保持完整历史、精确SHA与原有BASE_SHA检查。
2. 每次CI打印新增Git pack字节并写入运行摘要。超过32MiB警告，超过128MiB失败；失败后先看原因，不盲重跑或直接调高阈值。关闭本轮fetch自动维护，避免把本地重打包误算成下载。
3. npm优先本地缓存、关闭audit/fund请求，下载重试为0、请求超时30秒。没有新增远端依赖cache、后台服务、代理开关或整机流量账本。

`npm run check:network`进入原有check:rules；`tests/ci-downloads.test.mjs`使用真实离线Git执行工作流里的checkout脚本，并验证小增量不会重传大对象。保留旧流程负对照与删除保护的合同变异，防止检查永远为绿。

## 边界

新增pack大小是Git压缩载荷的近似落盘证据，不是完整网络字节或机场账单；失败产生的半包、协议开销、CI日志、AI及浏览器流量不在此数内。128MiB是下载后异常门禁，不是逐包实时配额。初次拉取可能比后续增量大，正常的大资产变动要看实际差异后处理。

调查确认本机runner保留411个pack共约5.36GB，对象重复显著；不据此声称它解释了整月200GB。默认不下载更多工具来监控流量。
