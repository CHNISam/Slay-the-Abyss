# 共享卡面原生还原与验收记录

本轮基线为 develop `d2e0baa3`，仅修改共享卡面装配、卡面显示绑定和对应工程门禁。规则数据、地图与主菜单不在改动范围。

验收以五类入口都使用同一组件、148×208不变、费用及文字仍由原数据/核心计算、原生装配可读回为准。原生实机验收由用户自行导入；本记录不将离线预览算作实机通过。

## 原生能力与差异

能力依据：本机MCP `src/scene/image-library/index.json` 的shape分类及 `shape_00.jpg`（2026-10-13采集），实查100001矩形、100002圆片、100003三角、100004四芒星、100006圆环。`docs/TOOLCHAIN.md`指定的MCP工作流和平台规则经离线读取；候选构建另保存原资源返回。只写副本，`MILIASTRA_ALLOW_LIVE_WRITE=0`。

一张战斗卡共119个控件（含容器），单容器最多29子控件，小于60门槛；并不代表多卡性能已经实测。装饰按角色/类型/稀有度/状态缓存，卡槽变化后重新绑定；弱键缓存不持有被销毁的原生控件。

原稿Card的296×416视图按1/2比较。原生外框保持148×208；沿用现有40费用圆、64高插画窗和132×92正文，原稿相应为30费用圆、79高插画窗。原因是原生中文最低14px与全文预算，不能把原稿2倍预览中的8–13px文字直接导入。该比例差异公开保留，未声称像素一致；未来如改窗高须同步重验全部长文卡。

CSS径向辉光、金属反射及SVG路径没有直接导入。标题使用八层原生图片色阶，费用反馈使用原生圆环缩放，徽记使用图库图形装配。类型图标沿用既有原生占位；下方SVG中的菱形只是预览标记。正式类型图标与发光强度须在游戏中核对。

## 用户导入检查

测试候选路径、hash与构建读回结果在本文件后续候选段记录。导入后分别检查：战斗不同类型/费用变化/不可打出、牌库长文与升级卡、奖励三张卡、商店七卡与买不起状态、锻造前后费用降低与确认结果。观察圆角接缝、角色徽记、尖底/拱顶、全文和类型标签，记录截图及本轮日志。检查1/5/10手牌时流畅度。

本轮不占用用户键鼠、不导入官方客户端；`verify:ui`需要候选hash对应的本轮实机截图和批准项，因此未宣称UI验收通过。平台性能、手机实屏及原生图形接缝仍待用户试玩证据。
