# PR #19 · 界面与美术规范（交接用）

本文件只管**美术与前端表现**。卡牌数值照抄铁甲战士（`data/cards.json`），战斗规则、地图生成、跨节点状态由 Lua 核心与其他任务负责；界面只**读状态、发命令**，不在界面里算规则。

| 交付物 | 路径 | 用途 |
|---|---|---|
| 可交互原型 | `docs/design/prototype/index.html` | 12 个界面：战斗、地图、奖励、选牌、营地、商店、事件、宝箱、精英、首领、通关、失败 |
| 界面截图 | `docs/design/screens/*.png` | 原型截图（1280×720），用于评审与对照 |
| 主题数据 | `data/presentation/ui_theme.json` | 颜色、字号、间距、动效时长、图库编号、布局坐标，全部在这一份里 |
| Lua 主题模块 | `npm run build:theme` → `build/lua/abyss_theme.lua` | 界面脚本 `require("abyss_theme")`；颜色已转成 0–255 的 `{r,g,b,a}` |
| 校验与测试 | `scripts/build-ui-theme.mjs`、`tests/build-ui-theme.test.mjs` | 字号不低于 14、颜色格式、图片编号在图库范围内；每个敌人、状态、药水、遗物、节点类型都有图标 |

原型的打开方式：用浏览器直接打开 `index.html`。顶部切换界面和设备画布，可以叠加安全区、手机平台按键区（估计）和控件标注（图库编号）。原型里的战斗只演示表现，规则以 Lua 核心为准。

## 1. 视觉方向：旅行者 · 岩

- **主色是岩元素的琥珀金**（`geo #F0B850`、`gold #E3B866`），底色是偏冷的深岩灰蓝（`backdrop #0F1117`、`panel #1C1E27`）。金色只用在重要位置：能量、当前节点、主按钮、标题和高亮数字。
- **卡牌稀有度沿用原神的星级配色**：基础灰、普通蓝（三星）、罕见紫（四星）、稀有金（五星）。原神玩家不用解释就看得懂。
- **卡牌类型用卡面插图区的底色区分**：攻击是暗红，技能是钢蓝，能力是琥珀。
- **形状语言是直角面板加细描边**，平台的纯色矩形 `100001` 就能画出来。圆形只用于能量球、费用、药水槽和地图节点。不依赖圆角和渐变（文本框背景的圆角是平台自带的，不要依赖它表达层级）。
- 卡牌 UI 是自己设计的，没有照抄原作的卡框、图标或配色。

## 2. 画布与缩放（最重要的落地规则）

- 以**手机 1280×720 为基准**设计。所有控件挂在一个 `stage` 容器下，脚本启动时按 `k = min(画布宽/1280, 画布高/720)` 设置 stage 的缩放（`game.GetUICanvasSize()`）。电脑 1600×900 用 ×1.25，主机 1920×1080 用 ×1.5，手机 16:9 用 ×1。19.5:9 这类更宽的屏幕在左右两侧留出底色。
- 底色矩形放在 stage **外面**，铺满整块画布，这样宽屏两侧不会漏出 3D 场景或平台小地图。
- **安全区**：左右各 40，上下各 20（`canvas.safe`）。可点击的控件都要在安全区内。
- 坐标约定：`ui_theme.json` 里的 `layout` 用**平台约定**，即离父容器中心的偏移，y 轴向上。原型 HTML 为了方便用左上角坐标，换算公式为 `x = left + w/2 − 640`、`y = 360 − (top + h/2)`。
- 如果确认 `devices` 能按设备覆盖 `scale`，也可以改用 `devices`；在验证之前，以脚本设置缩放为准。

## 3. Token（数值以 `ui_theme.json` 为准）

- **字号**：display 40 / title 30 / heading 24 / body 18 / label 16 / cardName 17 / card 15 / small 14。**最小 14**，测试会拦住更小的字号。
- **间距**：4 / 8 / 12 / 16 / 24 / 32；描边 2，细线 1。
- **动效**：fast 0.12、base 0.2、slow 0.35；横幅 0.9；伤害数字 0.6；血条残影延迟 0.25、时长 0.45；抖屏 0.15、幅度 6；敌人逐个行动间隔 0.45。
- **语义色**：hp 红、block 蓝、energy 琥珀、positive 绿、danger 红、buff 橙、debuff 紫。语义色和金色强调色分开使用。

## 4. 组件规格

**卡牌**（148×208，客户端模板 + 每张卡挂一份脚本）
- 结构从下到上：稀有度色框 → 名称条（高 30）→ 插图区（高 64，类型底色 + 类型图标 40）→ 类型条（高 18）→ 说明文字框（132×92，字号 15，开 autoSize）→ 左上角费用圆（40）。
- 状态：
  - 常态。
  - 悬停：电脑端上移 24、放大 1.1。
  - 选中：上移 36、放大 1.22、金色外发光。
  - 不可打出：降低饱和度并压暗，费用圆变暗，数字变红。
  - 已升级：名称变绿并加「+」。
- 说明文字里的数字用 `goldBright` 着色。最长的 42 字（reaper）在 autoSize 下能放进 5 行。
- `costMode=all_energy` 的卡，费用显示为 **X**。

**手牌**：中心 y=−250，最大宽度 820，牌距在 74 到 140 之间按张数计算，10 张也放得下。每张按离中心的距离旋转 2.5° 并略微下沉。

**拖牌与甩牌**（理想效果；「点一下选中、再点一下执行」始终保留作为保底）
- 原型里的行为：
  - 按住拖动 8px 后卡牌跟手，按水平速度倾斜（最多 14°），放大 1.1。
  - 攻击牌拖到敌人身上，敌人亮起金色描边，松手即对它打出。
  - 不需要目标的牌：拖过金色出牌线（y=430，左上角坐标）松手，或向上快速甩出（速度 > 1.1 px/ms），即打出。
  - 只剩一个敌人时，攻击牌向上甩出直接打它。
  - 没有打出的牌用 0.25s 回弹到手牌原位。
  - 截图见 `screens/drag.png`。
- 平台实现按三档降级，**先做第 C 档，再往上加**：
  - **A 跟手拖动**：前提是 `CursorDrag` 回调能拿到指针位置或位移（**未验证**）。拿得到就每帧 `SetAnchoredPosition` 跟随，倾斜用 `rotation`，出牌判定和原型相同。
  - **B 假拖动**：拿不到位置时用。卡牌 `CursorDown` 时抬起并放大，表示「抓起」；按住期间用敌人 `cursorArea` 的 `CursorEnter` / `CursorExit` 高亮目标；在敌人上 `CursorUp` 就打出，并用 0.18s Tween 让卡牌飞向敌人。不需要目标的牌，在出牌区的 `cursorArea` 上抬起就打出。手机上按住期间能否触发进入事件**未验证**。
  - **C 点选**：当前方案，必须可用。
- 无论用哪一档，出牌命令都一样（手牌序号、目标序号），差别只在表现层。

**战斗单位**：头像 120（首领 168，玩家 132）。名称在头像下方，血条 156×16 用开遮罩的图片横向填充。有格挡时，血条描蓝边，左侧出现盾牌数字（`102014` 染蓝）。状态图标 26，每行最多 5 个，层数写在右下角。

**意图**：放在头像上方 104，图标 40 加数字 22，多段攻击写成「5×4」。点击或长按显示说明。
- 攻击 `102035` 红；防御 `102036` 蓝；强化 `102020` 橙；削弱 `102045` 紫；未知 `100114`；沉睡 `100129`。
- 显示的伤害数字要包含敌人当前的力量，以及玩家身上的易伤加成，**由核心算好再给界面**，界面不自己算。

**能量球**：直径 88，放在左下（−548, −196）。有能量时显示琥珀色并带外发光，没有能量时变暗，中间写「3/3」。底纹是岩元素图标 `103005`。

**按钮**（`presetButton`，normal、hover、pressed、disabled 四个状态都要给，只给 normal 时鼠标悬停会消失）：
- 主按钮：琥珀底、深字。
- 次按钮：深底、金描边。
- 按下：缩到 0.96。
- 禁用：深底、灰字、灰描边。
- 「结束回合」在手里没有能打的牌时自动变成主按钮样式，提醒玩家结束回合。

**提示框**：电脑端悬停、手机端长按 350ms 弹出，宽 240，深色底加金细边，关键词金色。

## 6. 图库选型（`ui_theme.json` → `icon`）

- 都来自千星图片库。标了 `verify: true` 的组是根据缩略图选的，**需要在编辑器里看一眼确认**。确认后把 `verify` 删掉即可，不用改代码。
- 敌人头像：从「造物」类 112001–112077 里按长相对应。例如酸液团对应绿色史莱姆，石颚兽对应野猪，首领深渊守卫对应 112046。
- 地图节点和界面功能用单色图标（`102xxx`、`100xxx`），可以随状态染色。奖励、营地、宝箱的大图用彩色奖章（`105045` 篝火、`105043` 宝箱、`105046` 卡牌）。
- 金币用 `105077`。药水用 `111046`、`111047`、`111048` 三种瓶子，再按 `potionTint` 染色区分。

## 7. 动效与音效挂点（音效编号留给 TASK-4）

| 时机 | 表现 | 音效挂点 |
|---|---|---|
| 出牌 | 卡牌飞向目标 0.18s 后淡出 | `card_play` |
| 造成伤害 | 数字放大 1.5 后落回并上浮淡出（0.6s）；目标横移 10px | `hit` |
| 打在格挡上 | 蓝色「格挡」字样，不抖屏 | `block_hit` |
| 玩家受伤 | 抖屏 0.15s；血条先跌，残影 0.25s 后追上 | `hurt` |
| 获得格挡 | 盾牌数字弹一下 | `block_gain` |
| 回合切换 | 横幅从左滑入，停留后从右滑出（0.9s） | `turn` |
| 敌人死亡 | 0.35s 淡出 | `enemy_die` |
| 地图可前往节点 | 1.4s 一次呼吸缩放 | — |
| 胜利 / 失败 | 横幅后切到奖励或结算界面 | `victory` / `defeat` |

如果系统开启了减少动效，原型会关闭呼吸缩放并缩短各段动画。平台上要做同样处理，就在主题里加一个开关，把各项时长乘以 0.3。

## 8. 给界面实现者的接入约定（TASK-10 及后续界面）

1. `require("abyss_theme")` 取颜色、字号和布局，**不要在脚本里写死数字**，和 `abyss_data` 的约定一致。
2. 颜色这样用：`Color(c.r, c.g, c.b, c.a)`，数值是 0–255。
3. 界面需要战斗核心提供以下状态：玩家与每个敌人的 hp、maxHp、block、状态表，**算好修正后的意图数值**，手牌（卡 id、是否升级、当前费用、能否打出、是否需要目标），抽牌堆、弃牌堆、消耗堆的张数，能量，回合阶段。界面只发三种命令：出牌（手牌序号、目标序号）、结束回合、使用药水。
4. 事件队列：核心的 `state.events` 驱动动效。伤害、格挡、状态、死亡、洗牌、胜败各对应第 7 节里的一种表现。界面按顺序播放，**播放期间屏蔽输入**。
5. 手机没有悬停：一律「点一下选中，再点一下执行」，长按看说明。不依赖拖拽。
