# 批准稿与平台实现对照审计

日期：2026-10-23。范围：P0 集成冒烟工作树的 v4 实机事实，以及v5 生命/意图实机确认及 v6 待实机结算。本表不代表平台验收通过，也不重新定义视觉方向。

## 基准与判定

- 唯一视觉基准：[UI_DESIGN.md](UI_DESIGN.md)、[批准原型](prototype/index.html)、[批准截图](screens/)，数据值和交互规则仍以 `data/`、Lua 核心为准。原型商店商品、事件剧情和费用不能直接当作游戏规则补入。
- **源码**：控件或分支存在，只证明实现意图；**本地测试**：替身/规则或布局检查通过，不证明原生字体、图库效果、指针事件正确；**实机**：本轮用户试玩或截图证实。三层不互相替代。
- **缺失**：没有控件、逻辑或接线；**没显示**：已有源码，但实机看不到/被裁切；**观感差**：能显示或操作，但组织与批准稿有明显差异；**未测**：没有现场证据，不能预判通过或失败。同一屏可以有多种问题。
- **P0**：核心信息、可操作性或闭环阻断，冒烟阶段先解决；**P1**：恢复批准稿的信息层级与主要构图；**可延后**：装饰、细节和非必要动效。优先级不是重新设计许可，也不要求所有屏一次达到像素级一致。

## 已有实机事实边界

v1 启程无响应的根因为 `Color` 类型断言；v3 画面诊断明确报 `SetImage` 参数多传。v4 用户确认菜单→地图选路→战斗出牌/敌人行动，后续已到第 4–5 场战斗，经过商店且可离开，奖励卡加入、跳过可继续。v4 截图确认敌人意图出现“9（当前修”截断；头像下具体 HP/MaxHP、名称以及卡牌类型没有显示。玩家顶栏 `80/80` 可见，不能据此说所有生命数值都缺失。

后续用户已到达第 15 层最终 Boss 并战败；失败截图显示 `15/15`、生命 `0/80`、金币 `4`、卡组 `14`、遗物 `4`。点击“重新启程”正常回到新局地图，然后结束试玩。最小闭环、15 层到 Boss 后失败、重开已真实验证；这不等于击败 Boss 或完成全部节点/跨层状态回归。

v5 源码已增 `nativeText.lineHeight=40`、简短意图与点击完整说明，商店改五卡一排。用户已确认 v5 生命数字、意图和受伤更新正常；商店仍待实机。击败 Boss、胜利摘要仍未实机验证；v6 正式失败结算已实机进入平台官方失败界面，Boss胜利结算仍未测。本轮新客户端日志仍未找到，不能声称日志无异常。

现场证据索引：[P0 冒烟账本](../P0-SMOKE.md) 中的 `.artifacts/p0/menu-broken.png`、`menu-v2-broken.png`、`menu-v3-diagnostic.png`、`menu-v4-working.png`、`first-battle-victory-v4.png`、`battle-intent-clipped-v4.png`、`floor15-defeat-v4.png`，以及本会话用户的商店口述。`battle-intent-clipped-v4.png` 显示卡组从初始 10 张增为 11 张，结合用户确认，奖励入组已有实机证据。商店现场没有已归档画面时，只能写“用户反馈文字拥挤”，不能声称已逐像素核对实机商店。

## 跨屏机制与执行顺序

1. **P0 核心信息先可见**：同类原生短框问题应检查所有屏的文本高度，而不是只修截图中的一个 HP。字体不缩小来掩盖裁切；以平台实机验证 40 高策略，其他旧 28 高框保留待核查状态。具体 HP、敌人名、意图、费用/效果和操作反馈优先于装饰。
2. **P0 完整流程证据**：延续当前测试局记录逐层资源；最小闭环、15 层到 Boss 失败及回新局已验证，继续补原数值 Boss 击败与完整逐层账本。用户确认“经过商店”不等于买卡、买遗物、删牌及所有拒绝分支均通过。每个候选注明版本；v4 的操作证据不可替 v5 的视觉验收。
3. **P1 恢复现成构图**：奖励/选牌、营地预览、商店货架、事件/宝箱、结算与卡组查看均有明显整屏差距；不能称为少量文案问题。逐屏用批准稿已有组件、间距与主题 token 恢复层级，集中复用卡片和按钮，避免每屏另造布局。
4. **规则缺口单列**：`costMode`/条件卡当前被奖励/供货池筛除，显示 X 不证明完整费用规则支持；商店药水与战斗药水奖励没有相应交易/发放分支；Boss胜利正式结算仍未实测。这些不能归为“UI 丑”或靠控件生成解决。实际可玩卡池与全部卡牌数据量也必须分开报告。
5. **装饰延后**：完整拖牌 A/B 档、飞牌、血条残影、抖屏、开箱动效、音效可在主流程后补；C 档点选必须始终可用。已知本地动画 token 或图标 ID 存在，不等于平台效果已验收。官方图片 ID 应逐类截图核对，不能以 ID 在有效范围内代替语义正确。

当前结论：v4 已实际跑通最小闭环并抵达第 15 层最终 Boss，失败后能重开，功能进展有真实证据；平台 UI 距批准稿仍有跨屏的信息、布局和未实现项目。v5 解决的是有针对性的可见性与商店分层问题，其余差距需要按上表继续落实与取证。
