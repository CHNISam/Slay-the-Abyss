# 开场与战斗背景方案（M4 原生场景路线已确认）

**决策记录**：2026-10-27 已在 TASK-2.1/TASK-4.2 确认优先使用官方原生场景；2026-10-30 按用户复核补齐 M4 生产约束。技术路线已定，但不代表成品画面、官方导入或设备性能已经验收。

## M4 首发路线

- **素材**：优先千星奇域允许使用的原生 3D 遗迹、石台、山岩与门柱，配合平台环境/天空/光照和固定镜头；复用 [TASK-2.1 官方景片小样](../art/scene-spike/README.md) 与 [32 件实例的离线样板](../art/production-scene-3d.md)，不重复造模。32 实例只是候选，不是已实机放行的规模。
- **分工**：TASK-2.1 负责官方模型、摆放与导入/脚高/碰撞证据；TASK-4.2 负责开场与第一幕战斗背景显露、UI遮罩、场景切换与清理；TASK-4 负责前两幕整体品质及 PC/手机验收。
- **构图**：开场可见岩系封印遗迹/高塔远景；战斗保持低对比石地、左侧破柱、右后门洞与远山纵深，为左右单位、生命意图、顶部HUD和底部手牌留白。普通、精英、Boss以少量布景或原生环境参数区别，不新造每关大型背景；不增剧情、按钮或爬塔机制。
- **先解决遮挡**：核查 `scripts/ui-layout.mjs` / `scripts/game-ui-layout.mjs` 中不透明 backdrop 与实际组合宿主的层序；如果遮住3D，仅对需要显示场景的区域做最小适配，同时保留宽屏安全区、输入边界和其他页面底色，不能简单将所有页面全屏透明化。
- **设备成本**：同一候选先比较空场/小样/正式布景；真实PC及实体手机记录画质、FPS/帧耗时、输入响应、加载、重复进入退出后的对象清理，尤其避免与多卡/多敌状态 UI 同屏叠加成本超标。离线预览、导出或静态检查不能替代实机。

## 2D 方案仅作条件备选，不是首发任务

- **不新画整屏 2D 背景，也不把整屏 PNG 拟合为成百上千的 UI 图元**；现有卡牌与角色已有控件成本，这条路线不适合作为默认实现。
- 尚未确认存在可直接用作完整战斗背景的官方 2D 位图素材，或可直接导入任意整幅图片的原生平台通道。若未来找到了合法可用的现成素材和确实可用、同屏性能合格的通道，须由用户明确批准路线变更，再由 TASK-4.2 接手。未经批准不启动2D插画生产/审稿。
- 若原生场景只缺少局部层次，可以选用少量官方原生贴图、低图元剪影或局部装饰；先说明作用、控件预算和画面差异，再实机验收。旧 2D 方案的 1920×1080 构图及 1280×720、19.5:9 安全区参考不构成当前交付义务。

## 验收边界

记录素材 ID/来源、源码SHA与候选hash、官方导入及实体读回、固定镜头、地面脚高/遮挡/碰撞、真实叠UI截图、跨页面切换及清理、同候选 PC/实体手机性能和用户审阅；通过 `verify:ui` 与 M4 门禁。未完成的 AC 仍为待验，不能用 32 件样板离线校验或静态示意图冒充上线效果。
