# 开场与战斗背景方案（待用户审阅）

负责人：TASK-4.2 / @Codex，M4，2026-10-28。本文是方案，不是已完成插画或已通过的画面。用户批准前不生成或批量制作背景。

3D环境与2D插画是两种不同交付：TASK-2.1制作/验证官方模型，TASK-4.2整合环境显露；2D插画也由TASK-4.2负责方案、制作、正式界面装配和验收，不能以模型离线包代替插画。当前仓库没有经用户批准的开场及战斗2D背景成图。

建议先完成官方3D遗迹的显露与环境光验证，再决定是否增加2D插画。开场以璃月群山中的封印高塔为远景，战斗保持低对比石地、门柱及岩金残光；普通、精英、Boss共用遗迹语言，用少量布景/光线变化区分。遵守PR19、UI_DESIGN、WORLD_TREE与主题数据，不加新剧情、按钮或爬塔机制。

若用户决定制作2D插画，先各提交一张开场和普通战斗构图审查稿：开场避让中央标题和启程；战斗避让左右单位、生命意图、顶部HUD及下方手牌。原稿建议1920×1080，辅助1280×720和19.5:9安全区；这是构图规格，尚不是平台位图导入规格。精英/Boss只在普通稿可用后提交少量变体，不先批产。

技术选择：优先核实当前平台是否有真实原生位图通道。若没有，只考虑经审阅的低图元剪影/局部装饰，记录与插画原稿的差异；不把整屏PNG直接拟合成数千控件。B2的939控件和星陨剑单卡343控件已经说明成本风险，不能推导出背景上限。无法保真或超出同底图性能预算时，回到已验证的3D环境方案，交用户确认，不自行把黑底宣布完成。

批准记录必须说明：采用3D环境、增加2D插画或低图元降级中的哪种组合，批准的稿件/版本，差异和预算依据。此后才制作并在新完整游戏候选中装配；源码/素材hash、官方导入读回、同版本实机图、输入与性能比较、用户审阅和verify:ui分别留证。平台规格或用户决定缺失时，本任务保持待验，下一步是核实通道及审阅两张小样构图，不能持续写无条件的“待验证”。
