# M4 · 参考驱动的游戏 UI 高保真还原与主题融合

> 决策日期：2026-11-03。Owner 将 UI 美术生产主路线从「让模型从零原创设计」改为「成熟作品参考 → 高保真重建 → 主题融合 → 人工微调」。这是**生产方法**变更，不是现有设计稿、任务验收或发布许可的自动通过。首轮以地图页为可检验样板，成功后逐屏推广。

## 1. 决策与边界

- **设计来源由人类成熟作品主导**：先选有明确构图、层级、状态、材质与动效的现成参考；GPT/Codex 优先负责观察、还原、组件化、平台适配与回归，而不是凭空发明整页视觉。
- **第一阶段先学习原版《杀戮尖塔》的 UI**：建立独立的高保真对照原型，优先地图，再战斗、卡牌、奖励、商店、事件/营地、菜单、结算等；对照信息结构、状态反馈与操作，不改变现有游戏的真实规则。以相同场景/视口衡量保真度，不能把「100%」当作未经对照的承诺。
- **第二阶段再融合本项目主题**：保留原版交互的清晰性，使用岩系旅行者/原神世界观及现有主题体系；筛选其他优秀作品的局部设计，结合已有被 Owner 认可的地图、柔和粒子/光效/动效等效果做组合。未拿到昨天试验的真实截图/链接/代码时标记待输入，不能凭空认定某版「已批准」。
- **第三阶段由人工把关与原生落地**：统一全局视觉语言，避免杂乱拼贴；沿用游戏现有原生组件、官方素材与测试门槛。先交一屏可核对成果，再批量扩展，不一次性推倒全部 UI。
- 参考作品的截图与实现代码均有各自权利边界。可学习布局与交互方法，但**不能将网页/游戏的第三方图像、字体、纹理、音乐或完整源代码直接作为本项目可发布资产**，除非核实相应授权。原版内部临摹基线与可公开发布的融合版分离；保留引用、归属、许可核对，遵守 [LICENSE-SCOPE](../../LICENSE-SCOPE.md) 与 [THIRD_PARTY_NOTICES](../../THIRD_PARTY_NOTICES.md)。

## 3. 输入获取：不因无法读取源代码而卡住

1. **有真实可访问的网页式原型**：在已授权的浏览器会话中优先读取页面 DOM/结构、computed styles、尺寸、CSS、字体、状态切换和可合法使用的资源；同时截取固定视口的原图。站点的可访问代码只用于分析/在授权允许范围内复用，不把能读到误认为能复制发布。
2. **只有游戏截图或录像**：直接通过图像/视频还原层级、几何、排版、配色、透视、视觉焦点、状态与动效；补录缺少的 hover/点击/拖动/滚动、不同分辨率和过渡状态。不要把「截图网站源代码」假装成「游戏的 UI 源码」。
3. **Agent 无法打开某页或读取标签页**：将具体 URL 与缺失的状态记下；用户可手动打开对应标签页并允许读取，或提供截图/录屏。**同时先用已能取得的截图继续做视觉还原**，不无限寻找新工具或阻塞整批设计。
4. 对每份参考保留 `来源 URL/作者/作品/日期（可知时）/截图视口/场景状态/允许使用的范围/不确定项`。不要求为引用把未获授权的截图、网页源码或第三方资源原样提交到公开 Git 仓库。

## 4. 实施顺序

### A. 原版高保真基准（首轮只做地图）

- 固定 1280×720 的对照状态；必要时补 PC/移动端比例。制作隔离的 HTML/CSS/JS 或现有轻量原型切片；能直接利用现有合法组件时复用，不新引入庞大设计框架。
- 逐项比对：背景及留白、路线与节点间距、连接线、当前位置/已走/可选/未抵达状态、七类节点语义、标题/资源/HUD、缩放/滚动、点击和聚焦反馈、动效节奏。
- 原版截图只是**视觉对照**；原型数据可模拟，不能覆盖生产 `Map.view` / `Map.available`、两幕路径规则或业务逻辑。
- 交付同尺寸参考与重建的并排/叠层对照（无法提交原图时链接原图并提交自身输出）、可运行原型、差异清单。人工视觉检查后再进入融合；若某素材无法合法复用，以自有图形替代并标注差异。

### B. 岩系世界观与优秀局部设计融合

- 参考库只挑**具体解决问题**的局部：地图氛围/光影、可达路线反馈、信息栏、可交互节点、过渡动画；至少说明参考了什么、为什么适合。
- 以 `data/presentation/ui_theme.json` 为唯一主题源，延续岩金、深岩底色与现有官方素材优先规则。保留已满意的柔和粒子、缓慢上浮的非机械光效等成果，但须拿到真实候选证据后才能落实具体参数。
- 输出一张有明确主题辨识度、没有素材拼接感的地图候选；保留原版的信息架构与可理解的交互状态，关键操作可在手机触控上完成。

### C. 原生游戏工程集成

- 原型 HTML/CSS 不是千星奇域原生 Lua/UI。将**布局、层级、状态与动效参数**转换为项目已有主题/共享原生构建器，优先复用图库、控件和缓存，不直接往 Lua 粘贴网页代码。
- 保留原生安全区、文字可读性、控件容量、PC/手机输入、防误触、滚动与性能限制；不能为美术更改原版数值、地图规则、卡牌行为或发布配置。
- 先地图页面的完整运行时闭环，再逐屏推进战斗、卡牌、奖励和其他房间；复用共享组件，不为每一屏重复造一套皮肤。仅在新候选经 Owner 确认后更新正式 UI 基准。

### D. 验收与交付

- **保真**：同视口同状态的参考/重建截图、重要几何与状态差异、动效/操作录屏；定性检查，不凭空写「100%」或视觉分数。
- **功能**：地图状态、七类节点、跨幕、滚动/选择/取消、键鼠与触控回归；逐项说明真实交互和平台差异。
- **平台**：按 [TOOLCHAIN](../TOOLCHAIN.md)、[UI_DESIGN](UI_DESIGN.md)、[PLATFORM_PARITY](PLATFORM_PARITY.md)、[ENGINEERING](../ENGINEERING.md) 的已有命令与限制执行相关回归及真实候选验证。HTML、模拟器、GIL 写入、官方导入/ready、PC 和实体手机是不同等级证据；没有实测不标通过。
- **交付**：一屏先给 Owner 对照评审，确认视觉路线后继续推广；现有未获批准的历史视觉规范不自动作废。不要自动合并、发版或操作用户前台/设备。

## 6. 首轮完成定义与失败回退

- [ ] 地图参考链接、输入种类、视口及可利用的素材/许可边界明确。
- [ ] 同状态 1280×720 原版对照与本地高保真基线可评审；可运行交互而非纯静态截图。
- [ ] 主题融合候选保留已有认可特效与可读交互，Owner 能直接作 Go/Revise/No-Go 决定。
- [ ] 原生地图版本复用已有主题/控件，真实回归不倒退；官方/设备验收缺项如实登记。
- [ ] 通过一屏验证后按现有任务逐屏扩展，不批量覆盖尚未核实的正式 UI。

拿不到 DOM/CSS → 以截图/录像前进；拿不到某个参考 → 换同功能可获得的参考，不更改玩法；资源授权不清 → 只学习设计规律、用有权使用的资源重建；原生效果受限 → 给出可用的等价降级并记录差异；未获批准或未实测 → 不声称完成。
