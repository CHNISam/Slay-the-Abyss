## 后续版本怎样维护

- **何时升级**：只有确定一个新版本批次才升级；新增功能通常升 MINOR（`0.10.1 → 0.11.0`），纯修复升 PATCH（`0.10.1 → 0.10.2`）；不按日期、提交数或 Milestone 升级。
- **写哪里**：唯一玩家公告在 [CHANGELOG.md](../../CHANGELOG.md)，内部工程变更在 [ENGINEERING.md](ENGINEERING.md)，本目录仅列版本与 Tag/提交对比。代码版本来自 `package.json`，lockfile 与 manifest 必须同步。Release Please 仅作草稿，`fix(ci)`、`fix(engineering)` 等技术提交可能混入自动文案，必须人工删去；纯重构默认隐藏。
- **怎么操作**：复用仓库现有 `release-please` / `git-workflow` Skill 和 [发布操作单](../PUBLISHING.md)。真实千星奇域发布时间、作品 GUID、交付产物及证据另记在 `data/release/publications.json`；不使用 Milestone 充当版本号。
- **历史 Tag**：按上表固定原 Git 提交；这些追溯 Tag 是源码版本标识，不冒充旧版曾公开发布。不要移动已有 Tag，不建立 `archive/*` Tag。`v0.11.0` 只有在合并后完成必要 CI、候选交付/验收、固定精确提交时才创建一次注释 Tag，并更新本表实际链接。
- **游戏公告**：Alpha 构建读取本地 CHANGELOG 中不晚于当前代码版本的记录，即使历史发布凭证尚缺也能查阅；未有凭证时显示「版本日期」，不显示虚构的「发布日期」。
