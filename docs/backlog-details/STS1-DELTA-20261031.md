## 2. 乞丐零可删牌：M3 / High

**现有链**：`abyss_act2_events.lua` 的 `options` 在 intro 只按 `gold >= 75` 开放 donate；`choose` 扣75金币→gave_money→confirm→choose_card；choose_card 只提供 purge，且取决于 `#Purge.purgeCards(run)>0`。`view` 明确 `count=1, canCancel=false`，空候选带 `empty_purge_group_source_unproven`。

**确定差额**：零可删牌时，已经扣钱、唯一行动被禁用，当前状态没有正常完成出口。空牌组与全受保护/不可删牌组要各自覆盖；正常付款删牌并不是缺失。

**原版方法**：[Beggar.buttonEffect/update](https://github.com/aeubanks/sts/blob/319009d5df0a82d9fb0f23cc22322286c6a87ec0/events/city/Beggar.java) → [GridCardSelectScreen.open/update/callOnOpen](https://github.com/aeubanks/sts/blob/319009d5df0a82d9fb0f23cc22322286c6a87ec0/screens/select/GridCardSelectScreen.java)。原版事件在 GAVE_MONEY 打开删牌界面并将自身设为 LEAVE，但不能只据这一段推断空界面能正常退出；完整界面/取消/回退行为须核清。

**实现约束**：先保存真实生产入口红例，再定位收尾分支。正常75金币、删一张、瓶装保护规则不变；不能未经核实添加退款、伪造候选牌、缩事件池或重抽。若原版本身也卡死，需要明确记录本作防卡死偏差，而非照搬卡死当验收通过。

**复用测试**：`tests/two-act-selection-audit.test.mjs`、已有 `tests/lua/act2_events*` 与事件选牌 UI 夹具（执行前核对实际文件名）；新增边界必须运行当前生产 `Nodes/Run`，不是自造状态机。PR398 的广域遍历明确未证明这一边界，不能用42事件通过代替。
