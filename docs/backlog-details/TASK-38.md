## P1 手机横屏背景覆盖修复（2026-10-25）

用户报告的早期截图为 2556×1179，中间背景约 2268px，左右各约 144px 露出外部场景。原图未附于本轮，数值按用户报告保留。此项非当前通关阻塞，但正式发布前必须解决；复用 TASK-4 / TASK-38，不新建任务。

### 根因边界与改动

- 核对基线 `20aff96403729f57cb41905709e67af75d876a01`：`viewport-layout.mjs` 的 `canvasBackdrop` 已位于 `stage` 外，但没有拉伸锚点，初始为居中 1280×720；`abyss_viewport.lua` 在启动/画布改变时给它 `SetSizeDelta(width,height)`。该两文件自 PR29 后没有修复。旧回归仅检查收到的赋值，未检查背景对实际父容器的覆盖。
- 本机官方 API 文档 `mhtakr07vej4` 公开 anchorMin/anchorMax、sizeDelta、父子裁切语义；MCP `src/scene-save.mjs` 的 `clientState` 明确将 size 写为拉伸跨度之外的增量。`addClientUi` 生成的客户端根和外层客户端宿主均采用全范围拉伸、零增量，未发现项目把宿主主动固定为 1280×720。
- **已确认的代码缺陷**：背景依赖逻辑画布读数，不能自动跟随实际宿主范围，启动前也是固定设计尺寸。**尚待原生实测**：早期截图中的 144px 是否全部源自 API 画布与宿主范围差异，或另有宿主安全区/裁切因素；不能仅凭代码认定已消除手机截图里的空隙。
- 共享背景改为 `anchor.min=[0,0]`、`anchor.max=[1,1]`、`size=[0,0]`，保持主题纯色、无输入、第一兄弟层级；运行时移除背景宽高赋值，避免拉伸后再次添加整块画布造成重复放大。`stage` 仍为居中 1280×720，保持 `min(width/1280,height/720)` 等比缩放，不改变规则、字号、触点换算、安全区或页面控制器。
- 开场、地图、战斗、选牌、各房间、牌库、弹窗、胜败结算及其切换继续共用同一个背景；没有按页补遮罩，没有新增控件、纹理或逐帧工作。实际帧率尚未测量。
