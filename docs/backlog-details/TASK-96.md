# TASK-96：卡牌插画错误启用根因与防回退

## 已发生事实

Owner早已暂停卡牌插画，保留资产留待以后。本轮Windows构建者却把未合入PR419中声称“默认开启”的描述，当成了当前交付授权，主动向仍默认关闭的96411b6c源码传入 `--art-cards=true`。错误包buildId c266a8b4，SHA256 c27040bc551c476c66b59f102acc0e732ddddc85427b9a1db0793667238b6b2d；原命令和收据在本机 `.artifacts/windows-delivery-20261031/`。不是游戏运行时自行打开，也不是当前develop默认值回归。

错误包已撤回到固定交付目录的“已撤回”子目录。替换包700cbe30-4d38-47f3-9259-2892c499b87b，源码96411b6c74349f25e3434509dd922e423b47c45f干净，SHA256 245008292881ff7e8e7390ff8d7fd87b93a95935d7d8a00c422c815bb3fb0312；独立读取最终GIL确认cards=false、未启用卡图收据，328模块摘要全匹配。它仍是缺四项未合UI的临时Alpha，非完整最终候选，无官方导入/ready/设备/发布证据。

## 原因链

1. 决策来源判断错误：把PR作者描述的授权当作产品决定，没有保留“当前已批准配置”与“在途提案”的边界。赶交付时先扩大开启，再以技术预检成功自证合理，违反用户明确的暂停决定。
2. 产品决定只在对话、历史交接和文档中；文档同时保留历史全量接入、显式开启示例及后来的关闭决定。构建者需要自行解释这些历史，没有一个可执行的当前暂停约束。
3. CLI显式布尔值及旧registry/count/host参数被视作有效选择。原校验拒绝拼写/类型/参数冲突，但不判断产品是否允许启用。
4. 原生检查、哈希和读回验证回答“是否完整地打入了所选内容”，无法回答“是否应该选择它”。错误配置在生成Lua、收据、最终GIL中完全一致，因此技术检查通过并不能替代产品许可。
5. 本轮交付者未让实际开关通过独立产品配置核对，且临时Alpha缺UI/CI仍被先交付；这些缺项必须单列，不能因为可构建而称完整交付。

## 最小机制

- `data/release/candidate-art-policy.json` 保存当前暂停项，cards禁用适用于Alpha和Production；不影响源资产保留或离线UI实验。
- 正式toolchain入口先解析全部新旧选项，再在SDK启动/存档写入前检查策略。改变默认值或显式传true都不能越过；没有绕过环境变量或“赶工”选项。
- 完整构建返回、独立BGM封装及正式负载收据验证均检查策略；BGM缺完整源收据也拒绝，防止旧违规包重新封装。
- 策略缺失、格式错误均失败关闭。策略位于data，进入候选payloadDigest；以后重新启用必须明确修改并审查产品策略，不能仅改构建命令。
- 低级UI构建及注入mock的测试接口保留实验能力；其输出不具备正式候选许可，不能绕过上述入口直接交付。

## 证据与边界

新增真实CLI反例先在旧代码失败：显式开启、旧count、旧host、release标志，两条入口均越过产品暂停限制，直到预设缺SDK才失败。修复后同8条反例在写输出前因CANDIDATE_ART_DISABLED拒绝。

另验默认关闭/显式关闭能越过策略，避免全锁死假绿；缺失/畸形策略、关闭收据夹带卡图、策略变化影响摘要、独立BGM旧包/无来源拒绝均覆盖。独立复审 `/root/review_candidate_policy` 发现并推动修复BGM漏口，最终代码层PASS；精确SHA和CI见PR记录。

根因属于产品配置许可缺失及本轮错误决策，不修改通用全局Agent规则。不用新增大型系统掩盖当前纠错。完整CI、工程环境缺项和官方平台实测分别报告，不将专项绿灯称全量通过。
