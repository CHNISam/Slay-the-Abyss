# TASK-38｜手机横屏露底：同平台源码 A/B 实验（2026-10-31）

**优先级：Medium**（沿用现有 TASK-38，不新增任务）；**状态：待执行 / 未实机验证**。独立实验不阻塞当前集成发版，不改变正式候选。

## 现象与目标

2026-10-31 用户最新手机原图 `IMG_1229.png`：2556×1179，左右各约 144px 仍露出原神天空/草地，中央还有 16:9 内容区域与深色留边。截图属于聊天附件，含平台 UID，不把未经处理的原图提交到公开仓库。**这是实际运行包的失败证据，但尚未核实该包的 Git/GIL/脚本版本。**

**目标**：手机实际可绘制区域（尤其左右两侧）不再露出底层世界；背景可以延展，卡牌/文字/按钮保持比例、点击热区与安全区正确。系统或平台确实不可绘制的区域必须用同机证据说明，不能把猜测当限制。

## 最小实验任务

1. 先核实手机当前加载的 GIL、源 SHA、脚本指纹、是否旧包或旧 `external_lua_file`；对照现行 `game-ui.json` 与 `battle-ui.json` 出口。PR #207 已完成背景全拉伸锚点的**离线修复**，不得仅重复改锚点就报成功。
2. **优先直接移植外部可用源码做独立 A/B**：`Pairs` 的完整原生 Client UI（MIT），以及 `genshin-ugc-webui` 的 `fitfill/fitroot` 原生测量探针（MIT）；保留来源、许可证，按需取最小部分。与本项目当前候选在**同一台实体手机**上对照：物理截图边界、`GetUICanvasSize()`、根控件/画布边界、左右漏出的像素数。
3. 若外部原生 UI 同样受限，继续定位原生宿主/引擎画布边界；可用独立副本验证官方全屏动效等不同绘制路径，或合理的场景背景方案。是否采用由实机结果决定；不为实验引进整套新 UI 框架或非等比拉伸主舞台。
4. 找到有效路径后，向正式全游戏做**最小增量移植**并补防回归；优先保留现有 1280×720 内容布局、游戏规则和触屏交互。未验证成功之前不认定问题已修复。

## 交付及验收

- 给 Owner **可导入的独立实验 GIL**（以及适用时的完整游戏候选），附构建源 SHA、GIL SHA256、实际加载日志、明确导入和体验说明；独立存档，不覆盖正式候选。
- 同设备的原始对照截图或打码证据、左右露底的像素测量、运行时 UI 画布尺寸、结论与下一动作。区分 `PASS / FAIL / NOT_TESTED`，离线模拟和编辑器预览不代替手机结果。
- **成功标准**：手机开场、地图、战斗、弹窗、胜败结算可绘制区域没有天空/草地露底，内容无变形、触摸可用。若平台限制尚未突破，准确证明限制与替代方案的实测效果，不虚报全屏成功。
- 实验结束先提供 Owner 真机验收候选，不自行发布或合入。仓库本地/远端工作树、任务认领、CI、授权以及客户端输入协调遵守 `AGENTS.md`。
