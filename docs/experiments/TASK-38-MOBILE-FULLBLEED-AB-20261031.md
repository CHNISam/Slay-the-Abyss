## 现象与目标

用户 2026-10-31 的手机截图 `IMG_1229.png`（2556×1179）左右各约 144px 露出原神天空和草地，内部另有 16:9 内容留边。真实运行包的 Git/GIL/脚本身份尚待核对。原图含 UID，不直接上传公开仓库。

**最终目标**：手机可绘制游戏区域无底层原神世界露出；背景允许铺满，卡牌、文字、触摸热区和安全区不变形、不失效。当前 PR #207 的锚点修复只有离线证据，不能代替手机结果。

## 必须保留的因果顺序

### ① 原版基线（先做，禁止跳过）

选取 [Pairs](https://github.com/8itlab/genshin-miliastra-mcp/tree/eb05fd35075b2635e851a2f58b202ac2eadd187b/examples/pairs) 等同平台已有实现，固定上游版本，**先按原始源码与原始创建流程独立运行**。不使用本项目的 UI 布局器、背景修复或改写后的移植逻辑。仅允许让原版在目标存档运行所必需的 GUID、路径、模板索引等机械替换，并逐项记录。先提供原版实验 GIL，让 Owner 在同一实体手机上验证，截图和实际画布日志标识为 **UPSTREAM**。

注意：Pairs 原版 `dim.opacity=0.72`，底层场景会因有意半透明而透出，**不得把透明误判成未覆盖**。先保留原样作为基线；如无法清晰判断边界，再单独创建只把背景设为不透明的 **UPSTREAM-DIAGNOSTIC** 对照，不能把它叫作未修改原版。

### ② 最小移植（原版结果确认后）

只有基线身份和手机结果可追溯后，才把通过验证的最小 UI/背景结构**逐步移植**到本项目的独立测试副本，不整包替换正式 UI。每次只改变明确的适配变量，产出 **PORT** 的 GIL、差异和同机截图。按事实定位是移植过程、项目构建/宿主还是原版自身造成的问题。

### ③ 正式集成（移植实验通过后）

PORT 在同机确实解决露底，才最小改造正式 `game-ui.json` 构建链，交付 **INTEGRATED** 候选。分别核实开场、地图、战斗、弹窗、结算；保留主内容的正确比例、可触达性与输入坐标。

## 结果怎么判定

- **UPSTREAM 正常，PORT 异常**：优先排查移植、包装、依赖、父级及渲染字段的差异，不能推说原版有问题。
- **UPSTREAM、PORT 正常，INTEGRATED 异常**：重点检查正式游戏根容器、布局层级、构建复用和实际加载脚本。
- **UPSTREAM 本身异常**：先验证原版确实原样部署、图片透明度与平台/设备兼容性，再取其他独立实现或画布探针交叉验证；不能仅凭一个原版失败就断言引擎无法全屏。
- **所有原生方案都在相同边界失败**：再针对 UI 画布外区域实验官方全屏动效或其他平台允许的绘制路径；结论以手机实测为准。
