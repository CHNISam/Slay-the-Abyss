# Slay the Abyss · 首发范围与削减优先级

对标：**初代《杀戮尖塔》PC 正式版 Ascension 0 的数值、机制、敌人AI、随机规则与战斗反馈时序**，以原神千星奇域（Miliastra Wonderland）独立实现；不引入二代或自创平衡。详见 [RULE_PARITY.md](RULE_PARITY.md)。
硬线：**2026-10-30 完成发布准备并由人投稿**（官方截止 2026-11-02 11:59 UTC+8）。

## 本次参赛角色

- **首发**为《原神》的荧（Lumine），**岩元素形态＝初代 Ironclad 战士的职业规则包**；逐项使用该职业的初始牌组、遗物、卡池、费用、升级、战斗算法与数值。岩元素是人物/演出身份，而不是自行创造属性反应或加减数值。
- **不同元素承接不同职业规则包**：风＝Silent（毒/飞刀/弃牌）、雷＝Defect（充能球/集中）、草＝Watcher（姿态/占卜），均为**拟议映射，尚未决定要在本次比赛实施**。每种元素内可保留原职业的多种合法构筑；绝不把战士牌简单换色后称为新流派。
- 单手剑、岩系星陨剑等原神视觉、名称和世界观可包装原作卡牌效果；不额外赋予原作没有的攻击、元素反应、护盾或状态结算。原版相关数值/概率/触发顺序不可更改；未实现的效果不能放入合法可玩池。

## 必须保留的闭环（缺一不可）

1. 回合制卡牌战斗：抽牌/弃牌/能量/伤害/格挡/敌人意图/状态效果
2. **原版第一幕完整楼层**：第15层营地、第16层Boss、第17层Boss宝箱，含7类地图节点（普通战斗、精英、营地、商店、未知事件、宝箱、Boss）。仓库当前15层是**尚待修复的规则偏差**，不能凭旧M2/TASK-12口径称完全一致。
3. 营地：回血 或 升级卡牌
4. 商店：购买卡牌/遗物、删除卡牌
5. 战后奖励、遗物、金币、药水、卡牌升级、跨节点状态**真正生效**
6. Boss 战后正式结算；失败可重新开始

## 削减顺序（时间不足时从上往下砍）

1. 第二元素及对应新职业规则包（本次先保证岩元素荧）
2. 第二章节
3. 额外 Boss（首发只做 1 个）
4. 装饰性系统（皮肤、成就、排行榜等）
5. 过多卡牌变体（战士 75 张是完整对标目标，首轮保 30+ 可用构筑）

**不能砍**：卡牌构筑、分支地图、商店、营地、Boss 闭环。只有两个敌人的技术测试不算正式作品。

**明确状态保存边界（对应 TASK-14）**：首发必须保证同一局原版完整第一幕各层之间卡组、血量、金币、遗物、药水等状态正确保持；不要求玩家退出关卡后下次进来续上次的局。后者是官方奇匠 Lv.4 才解锁的「局内存档」，可延后，不得误认为 M2 必须等 Lv.4 才能执行。

## 内容规模标杆

- 普通遭遇：约 14 种组合
- 普通敌人变体：19 种
- 精英：3 种
- Boss：首发 1 个（但楼层/阶段/AI必须对齐原版）
- 战士卡牌：完整对标 75 张，首轮先做核心 30+（已纳入可玩范围的牌须完全一致）

上述遭遇规模是原任务覆盖目标，实际敌人/地图/奖励/商店规则必须再与初代原版逐项核对；不能用数量一致替代机制一致。

## 规则一致性是必选，不是可选扩展

参照 [RULE_PARITY.md](RULE_PARITY.md) 与 [data/SOURCES.md](../data/SOURCES.md)；原作对照在上游做完整来源核对，再以自动测试和千星实机验证。**本项目现状存在已知不一致项**，包括15层地图、固定金币和商店价格、固定敌人意图循环、敌人/首领部分特性省略等；它们是待审计/修复缺口，不是获准长期保留的自创规则。若平台确有无法等价实现的限制，应独立记录而非宣称100%一致。先保持当前P0主流程回归，后续按依赖修复真正影响通关/数值的差异。

## 参赛前条件扩展（Stretch Goals，不增加首发必过项）

**目标**：优先通过原版职业套件增加可重玩性；不同元素是不同职业，不改变原版数值/机制；第二幕在后。此节不改变 M0→M5 顺序和10/30内部提交硬线，未验收不加入首发声明。

**触发**：现有岩元素/首幕玩法和原版一致性的关键差异已验收、M4候选能完整实机运行，且10/29复验与10/30发布准备前仍有足够回归空间；否则延期，不占唯一主冲刺。

1. **E1｜第二元素＝第二职业（优先于第二幕）**：优先考虑风元素荧对应 Silent 全套核心规则，独立初始HP/卡组/遗物、卡牌及奖励池、毒/飞刀/弃牌机制，不能只换技能特效。需要时先验最小合法构筑和独立首幕通关，再决定是否扩量。雷＝Defect、草＝Watcher仅进一步候选。
2. **E2｜同元素合法子构筑**：岩元素的力量/多段伤害、格挡反击、自损换资源皆来自同一 Ironclad 原作卡池，尽量通过现有30+可玩卡与合法奖励自然出现；不为“凑流派”添加原创机制或改卡牌数值。额外增强不高于E1，也可在既有TASK-16验收中自然完成。
3. **E3｜第二幕**：只在上述可选内容和全部首发要求不受影响时考虑。新幕必须严格对照初代原作的地图/遭遇/事件/奖励/Boss和跨幕转场并完整实机通关，不能换贴图/复制第一幕冒充第二幕；第三幕不作当期承诺。

**验收**：E1 每种新增元素独立选择开局、正确载入职业独有规则和合法牌池，完成首幕实机通关；E2 所称流派必须通过自然奖励/商店构筑并能复现对照行为；E3 包括全幕Boss及结算。均需候选hash/种子/战斗与资源记录；不以数据目录、模型或调试作弊验证通过。

**管理**：查重现有 TASK-16、TASK-5 后，仅在触发条件通过时用 Backlog CLI 产生有限、非阻塞的可选工作项；不改变已承诺的主线 Milestone 关闭条件。

## 数值与资产原则

- **美术与界面设计依据**：用户已批准 [PR #19](https://github.com/CHNISam/Slay-the-Abyss/pull/19)（`develop` / `91ae349`）。全游戏遵循 `docs/design/UI_DESIGN.md`、原型及截图，主题数值统一来自 `data/presentation/ui_theme.json`。优先还原批准稿；受平台限制的差异需记录原因、降级与验证状态。
- **初代《杀戮尖塔》原版数值、概率、机制与战斗事件节奏为固定对照，不可自主调平衡或发明代替机制**。数据驱动实现并验证，来源不明确则标记未知和获取证据，不得编造。
- 打击手感可参考原作的动作确认、命中、伤害/受击表现、停顿和信息提示的功能与时间关系，但必须在千星内独立实现；**不得直接搬运原作或第三方代码、图像、音频、逐帧动画、受保护UI素材及长文案**。
- 复用明确获准使用的原神官方/千星资产；自制技能名/卡牌文字/美术等表现内容，保留允许使用的授权与来源记录。
