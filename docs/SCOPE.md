# Slay the Abyss · 首发范围与削减优先级

对标：初代《杀戮尖塔》第一幕，以原神千星奇域（Miliastra Wonderland）实现。
硬线：**2026-10-30 完成发布准备并由人投稿**（官方截止 2026-11-02 11:59 UTC+8）。

## 本次参赛角色

- 主角固定为《原神》的荧（Lumine），本次采用岩元素形态；风及其他元素延后。
- 保留单手剑普攻、重击和一般攻防；岩系招式先参考官方战技、爆发、天赋与命之座，能直接适配的优先采用，不把所有卡牌硬改成元素招式。
- “战士”仅指当前数值参照，不是角色身份。卡组改编不等于原版机制复刻；未实现的创造物、护盾、元素结算不得写成已有功能。

## 必须保留的闭环（缺一不可）

1. 回合制卡牌战斗：抽牌/弃牌/能量/伤害/格挡/敌人意图/状态效果
2. 15 层分支地图 + 7 类节点（普通战斗、精英、营地、商店、未知事件、宝箱、Boss）
3. 营地：回血 或 升级卡牌
4. 商店：购买卡牌/遗物、删除卡牌
5. 战后奖励、遗物、金币、药水、卡牌升级、跨节点状态**真正生效**
6. Boss 战后正式结算；失败可重新开始

## 削减顺序（时间不足时从上往下砍）

1. 第二角色及其他元素（本次只做岩元素荧）
2. 第二章节
3. 额外 Boss（首发只做 1 个）
4. 装饰性系统（皮肤、成就、排行榜等）
5. 过多卡牌变体（战士 75 张是完整对标目标，首轮保 30+ 可用构筑）

**不能砍**：卡牌构筑、分支地图、商店、营地、Boss 闭环。只有两个敌人的技术测试不算正式作品。

**明确状态保存边界（对应 TASK-14）**：首发必须保证同一局 15 层之间卡组、血量、金币、遗物、药水等状态正确保持；不要求玩家退出关卡后下次进来续上次的局。后者是官方奇匠 Lv.4 才解锁的「局内存档」，可延后，不得误认为 M2 必须等 Lv.4 才能执行。

## 内容规模标杆

- 普通遭遇：约 14 种组合
- 普通敌人变体：19 种
- 精英：3 种
- Boss：首发 1 个
- 战士卡牌：完整对标 75 张，首轮先做核心 30+

## 参赛前条件扩展（Stretch Goals，不增加首发必过项）

**目的**：在保证 2026-10-30 内部投稿硬线和 M0→M5 顺序验收的前提下，提高同一角色、同一幕的构筑变化与重玩价值。此节是可选候选，不修改 M3「第一幕完整通关」和 M4「候选验收」的完成定义；不得因为可选项未做完而阻塞主线、延迟封版或人工投稿。

**触发门槛**：至少先让 M3 的原数值首幕通关、结算与跨节点状态有有效证据，M4 的基础候选能稳定实机运行；P0 阻塞清零，且新增内容还能在 10/29 候选验收与 10/30 投稿准备前完成回归。任一条件不满足即保持候选/延期，不把 Stretch 移入唯一主冲刺。

1. **优先 S1｜岩元素荧的多构筑（不增加角色）**：利用现有卡牌、遗物、升级、奖励与商店系统，目标是在第一幕形成至少 **2 套机制和决策明显不同**、能够自然构筑的玩法。优先验证「力量积累＋多段输出」和「格挡积累＋格挡转伤害」；有余力再验证「自损生命换资源＋续航」。候选卡例：绷紧/燃血/恶魔形态＋双重打击/旋风斩，壁垒/掘壕/铜墙铁壁＋以身相搏，放血/祭品/控血＋收割。**数据存在不代表效果可执行或合法可获得**；先复用 TASK-16 的可玩牌和升级验收，核实缺失机制再决定是否补牌，不强制扩到75张。
2. **次选 S2｜完整第二幕**：仅在 S1 与主线都达到验收且仍有明确剩余时间时启动。必须具备章节转换、可玩地图/节点、足够区分的遭遇或意图组合、完整 Boss 战、奖励及正式结算/失败重开，且全程实机回归。不得以原样复制第一幕、换贴图或残缺半幕充作已交付；不为了多幕减少第一幕核心交付。
3. **内容成本控制**：优先让现有敌人在不同组合和意图中带来战术变化，不盲目增加新怪；但不得用“少怪”规避 TASK-15 原定遭遇验证或既定战斗密度要求。避免扩大核心系统/增加第二角色/牺牲战斗反馈和性能。

**扩展验收**：S1 每种流派至少提交一条通过合法奖励/商店获得关键构筑并完成第一幕的可复现路线（种子、卡组、关键遗物、候选 hash、官方试玩记录），能解释两套牌对选牌与出牌决策的实质差异；S2 需提交独立完整通关及章节连续性记录。新增内容导致已验收场景变化时，重做受影响的 M3/M4 回归。未达证据标准就不宣称多流派/多幕已经完成。

**任务管理**：先查重 TASK-16/TASK-5 等既有工作；只有触发门槛满足且存在独立缺口时，才用 Backlog CLI 建立可选、非阻塞的细粒度工作项。不可将开放的 Stretch 任务塞进 M3/M4 必选验收，不能改变唯一主冲刺规则。

## 数值与资产原则

- **美术与界面设计依据**：用户已批准 [PR #19](https://github.com/CHNISam/Slay-the-Abyss/pull/19)（`develop` / `91ae349`）。全游戏遵循 `docs/design/UI_DESIGN.md`、原型及截图，主题数值统一来自 `data/presentation/ui_theme.json`。优先还原批准稿；受平台限制的差异需记录原因、降级与验证状态。
- 复用成熟规则与有来源的基础数值，以数据驱动方式实现，不从零设计整套平衡。
- 复用原神官方允许使用的资产；代码、卡牌文案、美术自己实现。
- **不得搬运其他创作者的资产与存档。**

## 报告纪律

- 编译通过 / 写进存档 / 游戏里真的验证过，三件事分开报告。
- 内容缺口必须如实报告，不得把未完成功能宣布为通过。
- 官方允许最多投稿 2 件，已投稿作品不可更换；先完成第一件，第二件只在确有完整作品且时间允许时考虑。
- 发布与赛事报名由人完成，Agent 不得虚报投稿成功。
