# 岩脉残响 · 叙事接入

TASK-32 的本地实现。主角沿用岩元素荧，终点为现有 guardian「深渊守卫」。遗迹与封印故事是本作品原创设定，不是原神官方任务。

## 文案与落点

游戏文案唯一来源：[narrative.zh-CN.json](../../data/presentation/narrative.zh-CN.json)。原包长版、短版及状态均完整保留；本轮使用 compact，避免占用操作和统计空间。

| 位置 | 实际显示 | 保留内容 |
| --- | --- | --- |
| 菜单 | 岩脉失序，封印将破。循着共鸣，深入遗迹。 | 路线/构筑说明、出牌操作、启程 |
| guardian 入场 | 昔日的封印守卫，已被深渊侵蚀。 | HP、意图、手牌；一旦操作，正常提示优先 |
| 胜利 | 封印重燃，深渊退去。旅行者继续前行。 | 用时、层数、胜场、HP、金币、卡组、遗物、重开、正式结算 |
| 失败 | 封印尚未修复，旅途仍可重启。 | 同上，结算失败仍可重试 |
| 营地/商店/宝箱 | 各一行素材包风味 | 原有提示与动作 |
| 事件 | 圣职者/净化神龛各自对应短句 | 真实费用、条件和选项；净化选牌页只显示操作说明 |

不新增弹窗、剧情步骤、NPC、动画、玩法或控件，不改数值、奖励、地图与 RNG。普通/精英风味保留为资产，未额外插入战斗。叙事不写死层数，统计继续读取运行时地图。

## 复验入口与本地证据

运行 `npm run check`。`tests/lua/game_ui.lua` 通过现有控制器操作菜单、地图、战斗、奖励、节点、Boss、胜败、重开和正式结算；路由胜利用低 HP 测试夹具，不能当作原数值平衡通关。

`tests/game-ui.test.mjs` 会把实际控制器输出写至 `build/lore-preview.json`。它检查菜单、Boss、胜利、失败、结算错误提示的容量；节点测试也检查组合提示的容量。测试中预览的「平台结算暂不可用」来自没有平台回调的本地替身，不代表客户端实际故障。

2026-10-23 完整检查（8cedaaf 基线）：JS 274 项中 260 通过、14 因 Windows 符号链接权限跳过；Lua 23 组通过（含 game UI 10 项、node UI 17 项）；Python 16 项中 15 通过、1 因符号链接权限跳过。最终 PR 当前 SHA 另以 GitHub Quality 两项作业为准。

## 平台与实机边界

本轮未操作原神/沙箱，未构建或导入叙事 `.gil`，未真实试玩，未运行候选专属 `verify:ui`，不声明平台 UI 验收通过。沿用现有 P0/UI 验收任务收集下一候选的菜单、Boss、胜败截图及手机可读性；记录候选 hash，运行 `npm run verify:ui -- <候选.gil>`。先完成 M1 真实战斗关口，不以叙事增加阻塞。发布仍由人执行。
