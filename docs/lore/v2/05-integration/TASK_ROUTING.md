# Backlog 路由：沿用旧任务，分离叙事和机制

执行前运行 `backlog instructions overview`，通过 CLI 搜索最新任务，不允许直接编辑 backlog 下的 markdown。尊重最新交接与任务占用者，遇已认领内容不重复开工。

| 工作切片 | 首选任务落点 | 边界 |
|---|---|---|
| v1 compact → v2 四段原文完整显示 | TASK-32 旧验收已 Done；视任务 CLI 新建**小的 v2 增量任务**或受控重开 | 只修文案展示，不把旧 Done 当成功；必要阶段 M4 (m-5) |
| 商店老人可见形象 / 短对白 | 优先查 TASK-4、TASK-25 及现有商店 UI 打磨分工；不合适则新建小切片 | 不能另起 UI 框架，不能改变交易规则 |
| 窃金客偷金、逃跑、返金 | 现有 TASK-15 | 严格原版行为依据/测试，不凭剧情改数值 |
| 祈火徒仪式行为和遭遇池 | TASK-15 | 核算版本、效果、AI；不要另加未知信仰特殊 buff |
| 圣职者与净化神龛 | TASK-13.1 负责原版事件条件/交易机制；叙事文本仅跟随 UI 小任务 | 不得改收费、概率、选项以吻合文案 |
| Boss 阶段 / 结算 | TASK-17 负责战斗、结算行为；叙事仅 UI 层 | 不要改首领技能/难度 |
| 发布说明/封面介绍 | TASK-18 | 只在真正发布范围内用审定故事，不宣称新功能 |

## 优先级原则

- 当前唯一主冲刺仍是 **M1 主流程与实际平台闭环**；叙事 v2 不得抢占或阻塞 P0 实机验证。
- 独立可验收切片：1) 原文正确展示；2) 商人人物表达；3) 事件正文/结果；4) 现有敌人行为验证（按规则任务）。
- 先查 PR、分支、任务状态、测试覆盖，避免重做已认领部分；M4 的叙事和美术不能挤进 M1 未验收的大任务。
- 不改变原版数值/掉落/地图/行为随机性；如原版和当前项目已纳入内容矛盾（如 Looter 幕次），提交**事实+需裁决点**，不能擅选。
