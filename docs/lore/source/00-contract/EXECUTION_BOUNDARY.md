# 执行边界 / Minimal execution contract

## 目的

用几段短文案，为“荧探索深渊遗迹”建立明确的**进入动机—关卡探索—终点守卫—封印结局**，增强氛围与一局游戏的完整感。当前项目不是剧情向游戏；**不创建新系统**来表达这段世界观。

## 固定事实（2026-10-23 仓库快照；执行前核对最新 develop）

- 仓库：`CHNISam/Slay-the-Abyss`；平台：原神「千星奇域」UGC；角色：**岩元素荧**。
- `docs/SCOPE.md` 明确首发是卡牌战斗、分支路线、7 类节点、营地、商店、遗物、Boss、正式结算的闭环。
- `docs/HANDOFF.md` 指出 P0 实机主流程继续补 Boss 胜利结算、新客户端日志及资源账本；不能为了装饰工作延后它。
- 原始 UI 设计由 PR #19 已获用户确认；参照 `docs/design/UI_DESIGN.md`、`docs/design/PLATFORM_PARITY.md`、`data/presentation/ui_theme.json`。
- 当前数据中终点 Boss ID 是 `guardian`，表现名为 **深渊守卫**；不是《原神》官方同名角色宣称。
- Backlog 任务 `TASK-12.4` 已提出原版 17 层地图对齐；因此叙事**不能固定为 15 层**。

## 固定核心（不可因叙事更改）

1. **不动游戏机制和数值**：手牌、能量、回合、敌人意图、遭遇、RNG、地图、商店定价、事件选项和奖励均保持现有定义。
2. **不杜撰可操作能力**：没有动画、CG、过场、语音、剧情选择、可交互剧情 NPC，就不能假装已提供。
3. **不劫持 UI**：出牌、敌人意图、HP、费用、背包、结算、重新开始等关键界面信息优先；原型和视觉主题已锁定。
4. **不占用发布主线**：叙事属于 M4 完成度/呈现打磨，先做低风险文案资产；未验证平台能力不强塞新的复杂显示形式。
5. **不新造独立 lore 系统**：优先复用现有本地化/展示层、UI 标签和节点提示。

## 可做的最小改动

- 开始：菜单增加短提示或替换非关键说明的部分，**保留操作说明**。
- Boss：只有在已经有合适呈现挂点时插入一行登场气氛文字，否则保留为待接入候选。
- 胜利/失败：结果屏保留原有数据统计与平台结算能力，只新增一行不误导的旁白。
- 节点：只在已有提示位且能语义匹配时添加一句短背景；事件、商店的实际选项仍由核心生成。

## 交付与授权

本包是供 Agent 使用的**执行素材**。用户目前只要求压缩包，未授权代为更改远端仓库。本包本身不包含程序改动、PR 或 Backlog 状态变更。Agent 如后续被要求执行，须依目标仓库的 `AGENTS.md`、Backlog CLI 与现有 GitFlow-lite 流程实施。
