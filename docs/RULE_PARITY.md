# 初代《杀戮尖塔》规则一致性契约（Rules Parity）

状态：**目标约束 / 尚未完成的审计**。该文档不是当前实现已通过的声明。以初代 Slay the Spire **PC 正式版、Ascension 0** 为对照；不混入 Slay the Spire 2、模组或其他平台差异。逐条建立原作版本、来源、数据/算法、测试夹具与实机证据。若来源冲突，以可重复观察的原作行为优先，并记录证据；不能猜一个“接近”的数值。

## 固定核心：数值和机制不得自行改写

- **数值**：牌的费用、伤害、格挡、状态层数、升级前后、初始牌组与遗物；敌人HP与行动伤害、意图选择；金币、奖励、稀有度/抽取权重；地图楼层与节点分布；商店价格分布；事件分支；药水/遗物的触发、效果与稀有度。对随机范围和分布严格实现来源规则，不能把均值当固定值；核实原版取整与结算顺序。
- **机制**：抽/弃/消耗、手牌上限、回合开始/结束、伤害/格挡/状态计算及触发时序、敌人意图算法、分段/形态变化、奖励选择、存档/重开、职业专属资源。不能把复杂AI改成固定循环、把敌人特性删除、把原作行为替换成新的原神元素反应；原版不存在的技能强化不能混入核心平衡。
- **优先级**：当前只需要对**已选定为可玩的第一幕和岩元素荧/Ironclad内容**做到逐条一致；不以完整75张、全部职业或三幕内容作为10月30日前必须实现的总量。但纳入可玩池的每张牌、每个敌人及其所有可触发效果，必须对齐原版；不支持的内容不得出现在合法池或声称已复刻。
- **换皮允许面**：技能名称、角色/背景、剧情文案、元素视觉、独立创作的卡面和受授权的原神场景/角色资产可以变化；不可因此修改被包装的规则语义。界面可适配千星输入方式，玩家可观察的策略选择、数值和结算结果应保持一致。

| 元素候选 | 初代原版职业 | 保留的完整规则边界 |
| --- | --- | --- |
| 岩元素荧（**首发已确定**） | Ironclad 战士 | 独立卡池/初始套牌/燃烧之血、力量、格挡、自损、消耗等原版机制 |
| 风元素荧（候选） | Silent 猎手 | 对应职业的初始套牌与遗物、毒、飞刀、弃牌及其精确触发/数值 |

“元素”是**一整套职业规则包的外观身份**，不是在 Ironclad 的现有牌上添加原神元素属性和新反应。每个职业内部本来可以形成多种合法构筑，不以“一个元素只准一种卡组”限制原作。每次开局选择的职业应决定初始血量/套牌/遗物、奖励/商店卡池和专属机制；未经原作许可的跨职业混池不是默认规则。

## 验收与变更门槛

1. **规则对照账本**：按卡牌、敌人、地图、事件、商店、药水、遗物、职业分组，记录原作来源/版本、输入、期望结果/概率、当前代码位置、状态（PASS/FAIL/UNVERIFIED/PLATFORM-LIMITED）、对应自动测试与平台证据。
2. **确定性测试**：包含升级前后、状态叠加/衰减、边界值、不同回合顺序、敌人阶段切换、卡奖励/商店概率和稀有度、跨节点结算；随机场景使用固定种子及足够样本验证，不把单次命中当成概率正确。
3. **原作对照**：关键动作至少提供可复现的原版观察或权威规则来源与相同输入输出的验收例。对未知值保留Unknown；不要“按感觉调平衡”。
4. **千星真实游戏**：每个进入候选的规则经过本地检查、候选导出、官方导入、游戏内操作与日志的适当层级验证；不能以构建通过冒充手感或通关验收。体验/反馈依靠同候选的实机片段与用户验收。
5. **范围控制**：先修当前第一幕的实质性规则差异，优先处理直接影响通关/体验的项；后续元素职业、第二幕为非阻塞扩展。需要调整任务里程碑时，先运行 `backlog instructions overview` 和对应指南，只使用 Backlog CLI 更新；保留原有任务历史和证据。
