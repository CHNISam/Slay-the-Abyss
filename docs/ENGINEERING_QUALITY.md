# 工程质量基线与验收

本机制只检测工程质量，不重构玩法。新增数值指标目前为 **report-only**：退出码0表示本轮数据完整、基线可比较且未触发已有规则，不表示大模块、长构造器或全库复杂度已经达标。

## 使用

```powershell
npm ci --ignore-scripts
npm run setup:lua-static
npm run check:quality
```

日常报告只需上述命令。正式工程验收仍用 `npm run check:engineering`：先写质量报告，再运行原架构、静态与既有复杂度硬门禁、四类语义变异和原生UI合同检查。完整Quality、玩法回归与平台验收仍各自负责原范围。

输出 `build/engineering-quality.json` 和 `build/engineering-quality.md`。JSON保留全部模块、函数/初始化块、依赖边、环内调用点、告警及差异；Markdown展示指定模块和前15个热点，不截断JSON数据。CI两个系统的第一片上传报告，失败路径也尝试保留已生成报告；更早的安装失败或作业取消可能根本没有报告，不能视为通过。

入口调用现有 `analyzeSources`、`runStatic` 和固定 `luaparse`；不新增依赖、不自写复杂度算法。全部重新读取源码和执行Luacheck，不消费残留build报告。当前本机一次报告约6秒；这是采集耗时，不是整套CI耗时，双系统/其他机器未作性能承诺。

## 固定测量口径

- 递归发现 `src/lua/**/*.lua`，无排除文件。空扫描、链接条目、无法解析的源码、重复模块身份失败；新辅助文件自动进入测量和架构分类检查。
- 文件行数包括空行、注释，终止换行不额外算一行。源码摘要将CRLF规范为LF，Windows/Linux可比较；源文件不被改写。报告中摘要是规范化源码摘要，不冒称原始磁盘byte hash。
- AST记录所有具名、匿名、嵌套函数和初始化块，函数行数为完整起止行（含内部函数）。`new/create`只是构造器名称标签；所有函数都报告跨度，改名无法消除长函数。AST范围与Luacheck各自测量不同属性，不相加伪造一个新复杂度数字。
- 复杂度完全来自固定Luacheck。每个AST函数关键字及初始化块必须恰好对应一个W561测量；main与首位function同坐标仍是两个不同对象。中文、emoji、组合字符按Unicode列转换为AST的UTF8字节位置。缺测、重复、错位、未知文件/格式都失败。
- 函数对应关系用词法父级、名称和同名出现次序；行移动不会自动变成新增函数，改名/搬到其他模块则明确报告删除与新增。此身份不是语义等价证明，不能凭它断言重构行为不变。
- 依赖边复用现有作用域AST结果，全图SCC包含已审查延迟导入。全库唯一依赖对的增减另报；调用点及延迟标记保留于环数据。原架构的即时加载循环硬门禁保持原样，不用延迟白名单把完整图说成无环。
- 静态告警按文件/行/列/代码/信息的多重集合比较，新增和移除分列。行位迁移按一增一减，不自动猜测或豁免；原 `config/luacheck-baseline.json` 的精确告警门禁继续执行，不自动更新或增加条目。
- 检测口径/工具版本不匹配拒绝比较；`.luacheckrc`和固定工具配置摘要变化失败。其他检测脚本、架构分类和静态基线输入的变化列在 `ruleChanges`，必须审查实际diff，摘要变化本身不证明规则变松或变严。

## 新硬门槛何时启用

本轮不把现有2071行等债务数值设置成“允许上限”，也不提前加全库15上限制造失败。新文件行数、完整函数/构造器跨度、全库函数复杂度及完整依赖环的**数值硬门槛尚未启用**；当前新增失败仅保护测量完整性与可比性，已有门槛不变。

对应重构完成后，在同一个重构PR或明确承接的规则PR中：

1. 保留本冻结基线，提交重构后的完整报告；以最终绝对值验收，不以降幅代替达标。
2. 审查受影响的完整职责及全部提取helper，结合模块增减、函数增减、依赖边和告警变化判断有没有转移热点。无意义切碎模块即使数值下降也不能通过职责验收。
3. 取得行为回归、构建模块完整性与当前SHA验证证据后，按已验收职责明确绝对限值并接入现有硬门禁；匿名、嵌套函数和初始化块仍完整测量。给旧高值和超限helper各补真实失败对照。
4. 启用规则需审查diff，不改文件排除、增加白名单、缩小受检职责或改测量口径凑数。没有证据的职责保持待治理，不写“整体完成”。

CLI只有可选基线文件路径供独立比对，无自动刷新基线、忽略文件或放宽阈值参数。不得覆盖冻结基线消除差异；确需另立历史切点时，保留旧快照、明确原因并单独审查。

工具能发现数值与结构变化，不能机器证明拆分有业务意义、规则等价或平台体验合格；这些仍由职责审查与相应回归证明。
