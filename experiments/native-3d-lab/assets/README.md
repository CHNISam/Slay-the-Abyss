# 一个原生纹理底板降级小样

选型：用已实际查看的官方图片 **107134**（紫蓝纹理底板）加一个可读性遮罩，展示不同美术方向的低成本降级。若正式菜单放弃自制风景，可以采用此类路线；它不是将原风景无损压成一张图。本轮不再重复卡框/图标小样。

**当前实验从战斗开始；战斗背景本来已有“单张官方图 + 遮罩”路线。** 因此战斗内切换此样张不证明节省 4498 控件，也不证明减负。下表只是相对菜单 4500 行预算背景的静态机会，不是当前画面或候选的实测收益。屏内只报告这个样例自身有 2 个图片控件。

原图依据为 `plate-colour_03.jpg` 底排，ID 在图片下方可见。该文件是既有工具保存的官方编辑器资源库截图，本目录复制原文件并在 `specimen-receipt.json` 保留 SHA256。`107134` 是原生图库引用，不是把截图或任意 PNG 导入客户端。

| 源码机会口径，非本次 battle A/B 实测 | 自制菜单预算背景路线 | 不同内容的纹理底板 |
|---|---:|---:|
| 图片图元 | 4,500 | 2（原图 + 遮罩） |
| 含根容器的控件下界 | 4,501，另有分组 | 3 |
| 可避免的图片控件 | — | 4,498，约 99.956% |
| 独立素材数据行 | 4,500 | 1 个原生图片 ID |
| 图元分批创建/逐帧揭示 | 现有 `abyss_menu_background` 适配器 | 无需此图元构建流程 |

基线来自 `art/performance/background-budget-v1.json` 的实际 4500 行、原 `scripts/official-background.mjs` 与 `src/lua/abyss_menu_background.lua`，不是推算 GPU 负载。小样控制描述见 `specimen-template.json`。创建/读回原生模板已通过，模板编号与 GIL 副本摘要见 `specimen-receipt.json`。原生客户端视觉、手机、官方负载均未验证。

集成接口：

- `specimen.mjs`：`assetControls()` 返回静态 UI 节点；`installAssetControls(layout)` 将其放在原背景上、`battlePanel` HUD 下；`materialSample` 提供引用与证据元数据。
- `runtime.lua` 打包为 `abyss_3d_material_sample`：`toggle(script.object,true/false)` 返回可直接显示的说明，记录并恢复原背景可见性，保留角色 HP、意图、卡牌和命中面。页面重绘后若仍处于比较态，由父实验重新调用 `toggle(...,true)`；切模式、恢复原画或销毁前调用关闭。
- `probe.mjs [base.gil]` 只在 `.artifacts/native-3d-material-probe/<uuid>` 写存档副本，并核对原生模板完整读回。

为了同档切换，原方案的模块和素材仍保留。**仅隐藏 A 并不等于释放其缓存、减少整包体积或降低官方容量**。要测最终迁移后的净成本，应另建不打包该高图元背景的迁移候选；当前实验只报告源码可省控件和实际同档体验。

这不是完整场景美术。若原生 3D 环境能够提供更好空间感，应优先使用环境而非把底板当风景；本小样专门验证“背景无需几千图元”的最低维护成本路线。
