# 四幕敌人外观覆盖提案

本目录只评估表现，不改规则、内部 ID、数值、卡牌/关卡引用，也不将比赛范围扩为四幕。

`catalog.lua` 读取实际 Combat 共用的 `abyss_combat_catalog` 和 `abyss_combat_enemy_setup.register`，获得 **67 个注册敌人定义**；不是仅扫描第一幕 JSON 中的 23 个。JSON/CSV 按相同集合严格校验，不允许漏项或多造 ID。

| 口径 | 数量 | 证明范围 |
|---|---:|---|
| 不重复规则定义 ID | 67 | 实际完整注册目录 |
| 建议原生模型外观 | 56 | 17 种复用外观；允许多敌共用，不要求还原原型 |
| 其中已读模型动画目录 | 45 | 10 种外观的目录记录；不等于每个动画已实机播放 |
| 仅目录/结构候选 | 11 | 7 种尚未读动画或不是复杂造物的外观，各有已读模型回退建议 |
| 建议保留简洁 shape | 11 | 哨卫/球体/多面体/飞刃/六焰核等，避免强换不匹配的人形骨骼 |
| 阶段附表 | 12 个定义 / 30 状态 | 不扩充规则 ID 分母，独立记录复苏、分裂、飞行、变形、唤醒和离场等 |
| 已完成整个类型矩阵的官方验收 | 0/67 | 现有少量模型和动作探针成功不能替代四幕逐类覆盖验收 |

`enemy-coverage.json` 保留内部 ID、原名、幕与定义来源、候选官方 ID/名称、复用组、缩放、已读动画、现有自制 2D 绑定和状态。`recommended` 是表现选型建议；`structural-only` 是还需验证可控能力的候选；所有映射的完整类型验收均为 `runtime-unverified`。`displayName` 仅供新的显示层绑定选择，原数据名、原始 `sourceId`、内部 ID 不写回。

幕字段描述定义来源及源码已明确的常见复用，不声称枚举全部随机房间出现次数。召唤物 `torch_head`、`bronze_orb`、五种小魔、`snake_dagger`、分裂大小史莱姆及第三幕 `jaw_worm_hard` 均进入 67 个定义分母。一个房间的三只同型敌人、运行时 `_1/_2` 后缀不额外算定义；容量测试仍须按真实最大同时在场数取证。

阶段表特别区分苏醒的羽冠、暗影的 `halfDead` 和永久死亡，不能把原生销毁动画直接绑定所有 `hp<=0`。史莱姆分裂生成的子定义已在主表；不会给“第二形态”另造规则 ID。

复现：先沿用项目入口生成 `build/lua` 数据，再执行：

```powershell
node experiments/native-3d-lab/coverage/build.mjs
node experiments/native-3d-lab/coverage/verify.mjs
```

本机 D 盘既有目录及本轮上游 `f32c8b05415b64e3c2698535c1aee45b105f3304` 的目录规模一致：48 种复杂造物、1,590 图片、1,986 限时 + 1,209 循环特效。报告以实际已读 D 盘文件摘要为准，不把新版本模型名/未读动画 ID 猜成可用。资产名称表注明源自 `hang-ZYM/qianxing-format-docs`，CC BY 4.0；游戏资产的权利仍归米哈游，项目原有非商业许可保持不变。

原生路线可大幅减少逐敌自制图元；它仍需要通用实体生命周期、技能目录、武器挂载、阶段状态与 5 槽以上容量等适配。覆盖提案不证明画质或手机性能优于现方案。
